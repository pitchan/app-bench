7. Functional requirements — History

The history is a list of steps. It is empty on a new sheet.

FR-HIS-01 History steps

  • Statement: The system shall record exactly one step for each of the actions below, and no step for anything else (moving or extending the selection, copying, cutting, cancelling an edit, an action that this specification says changes nothing).

    Action A step is recorded
    Commit of an edit (FR-EDT-03) when the raw content of the cell changes
    Clear (FR-EDT-06) when one cell at least of the selection is not empty
    Format (FR-NUM-03) when the format of one cell at least of the selection changes
    Insert row, insert column, delete row, delete column (FR-STR-01, FR-STR-02) always
    Paste (FR-CLP-01, FR-CLP-03) always

    A step holds the state of the sheet (the raw content and the format of every cell) and the selection (anchor and active cell), both before the action and after it. "After" is taken when the user action that caused the step is complete: for a commit by Enter or Tab, after the active cell has moved; for a commit caused by a click on a cell, after that click has set the selection. When a step is recorded, the steps that could be redone shall be discarded.

  • Rationale: Every change of the sheet can be taken back, one user action at a time.

  • Verification: Test

  • Acceptance criteria:

Scenario: What counts
  When the page loads
  Then undo-button is disabled and redo-button is disabled
  When the user clicks cell B2
  And the user shift-clicks cell C3
  And the user clicks button copy-button
  And the user presses Delete on the grid
  Then undo-button is disabled
  When the user enters "1" in A1
  Then undo-button is enabled
  When the user enters "1" in A1
  And the user clicks button undo-button
  Then cell-A1 shows nothing
  And undo-button is disabled

FR-HIS-02 Undo

  • Statement: When the user clicks undo-button, or presses Control+Z on the grid, while a step can be undone, the system shall restore the state of the sheet and the selection that the most recent step that is not undone holds as "before", and shall show every cell, name-box, formula-input and format-select accordingly. That step can then be redone. The clipboard shall not change. While no step can be undone, the system shall disable undo-button.
  • Rationale: The user goes back to exactly what was on the screen.
  • Verification: Test
  • Acceptance criteria:
Scenario: Undo a row deletion and a commit
  Given the user enters "5" in A1
  And the user enters "=A1+A2" in B1
  And the user clicks cell A1
  And the user shift-clicks cell H1
  When the user clicks button delete-row
  Then cell-B1 shows nothing
  When the user clicks button undo-button
  Then cell-A1 reads "5"
  And the raw content of B1 is "=A1+A2"
  When the user clicks cell A1
  And the user shift-clicks cell H1
  And the user clicks button undo-button
  Then cell-B1 shows nothing
  And cell-A1 reads "5"
  And the selection is "B1"

In this scenario the first undo restores the selection A1:H1. The second undo takes back the commit of B1: the selection before that commit was B1.

FR-HIS-03 Redo

  • Statement: When the user clicks redo-button, or presses Control+Y on the grid, while a step can be redone, the system shall restore the state of the sheet and the selection that the most recently undone step holds as "after". That step can then be undone again. While no step can be redone, the system shall disable redo-button.
  • Rationale: An undo made by mistake is taken back.
  • Verification: Test
  • Acceptance criteria:
Scenario: Undo twice, redo, new action
  Given the user enters "1" in A1
  And the user enters "2" in A2
  When the user presses Control+Z on the grid
  And the user presses Control+Z on the grid
  Then cell-A1 and cell-A2 show nothing
  When the user presses Control+Y on the grid
  Then cell-A1 reads "1"
  And cell-A2 shows nothing
  And the selection is "A2"
  And redo-button is enabled
  When the user enters "7" in C3
  Then redo-button is disabled
  And cell-A2 shows nothing

FR-HIS-04 History limit

  • Statement: The system shall keep at most 20 steps that can be undone. When a step is recorded while 20 are kept, the system shall discard the oldest one.
  • Rationale: The memory used by the history is bounded.
  • Verification: Test
  • Acceptance criteria:
Scenario: Twenty-one commits
  Given the user enters "1" in A1, "2" in A2, and so on up to "12" in A12
  And the user enters "13" in B1, "14" in B2, and so on up to "21" in B9
  When the user clicks button undo-button 20 times
  Then undo-button is disabled
  And cell-A1 reads "1"
  And cell-A2 shows nothing
