5. Functional requirements — Formulas

5.1 Language

FR-FML-01 Formula syntax

  • Statement: The system shall treat a committed string that starts with = as a formula and shall decide whether it is valid with the tokens and the grammar of 02, section 2.6. If the formula is not valid, then the system shall give the cell the value #SYNTAX! and keep the string unchanged as raw content.
  • Rationale: A formula that cannot be read is shown as such and can be corrected as it was typed.
  • Verification: Test
  • Acceptance criteria:
Scenario: Not valid
  When the user enters "=1+" in A1
  And the user enters "=(1+2" in A2
  And the user enters "=1 2" in A3
  And the user enters "=SUM(1,,2)" in A4
  And the user enters "=A1(2)" in A5
  And the user enters "=1." in A6
  And the user enters "=A$+1" in A7
  And the user enters "=" in A8
  Then cell-A1 to cell-A8 all read "#SYNTAX!"
  And the raw content of A3 is "=1 2"

Scenario: Valid, with an error value
  When the user enters "=foo" in B1
  And the user enters "=foo(1)" in B2
  And the user enters "=SUM()" in B3
  Then cell-B1 reads "#NAME?"
  And cell-B2 reads "#NAME?"
  And cell-B3 reads "#ARGS!"
  And the raw content of B1 is "=FOO"

FR-FML-02 Canonical form

  • Statement: When a valid formula is committed, the system shall store its canonical form (02, section 2.6.4) as raw content: no space outside string literals, names, references, logical literals and #REF! in capitals, number and string literals as typed, ranges normalized with each $ sign kept on its column part or row part.
  • Rationale: A formula has one writing, which the rewriting rules and the formula bar share.
  • Verification: Test
  • Acceptance criteria:
Scenario: Canonical writing
  When the user enters "= if( a1 >= 10 , ""big"" , sum( $b$2:b1 ) )" in D1
  And the user enters "=Sum( c3:a1 ) + 1.50 + .5" in D2
  And the user enters "=""a  b"" & true" in D3
  And the user enters "=b007" in D4
  Then the raw content of D1 is "=IF(A1>=10,""big"",SUM($B1:B$2))"
  And the raw content of D2 is "=SUM(A1:C3)+1.50+.5"
  And the raw content of D3 is "=""a  b""&TRUE"
  And the raw content of D4 is "=B7"

FR-FML-03 Arithmetic operators

  • Statement: The system shall evaluate +, -, *, /, ^, the unary signs and % with the precedence and the associativity of the grammar of 02, section 2.6.2, and the results of 02, section 2.7.4.
  • Rationale: An expression has one meaning.
  • Verification: Test
  • Acceptance criteria:
Scenario: Precedence and associativity
  When the user enters "=2+3*4" in A1
  And the user enters "=-2^2" in A2
  And the user enters "=2^3^2" in A3
  And the user enters "=2^-2" in A4
  And the user enters "=10-4-3" in A5
  And the user enters "=50%*200" in A6
  And the user enters "=-5%" in A7
  And the user enters "=2*-3" in A8
  And the user enters "=--3" in A9
  And the user enters "=100/8/5" in A10
  Then cell-A1 reads "14"
  And cell-A2 reads "-4"
  And cell-A3 reads "512"
  And cell-A4 reads "0.25"
  And cell-A5 reads "3"
  And cell-A6 reads "100"
  And cell-A7 reads "-0.05"
  And cell-A8 reads "-6"
  And cell-A9 reads "3"
  And cell-A10 reads "2.5"

FR-FML-04 Operands of arithmetic

  • Statement: The system shall convert the operands of the arithmetic operators to numbers as 02, section 2.7.3 states: a logical value to 1 or 0, blank to 0. If an operand is a text, then the system shall give #VALUE!, even when the text is written like a number.
  • Rationale: A text is never silently read as a number.
  • Verification: Test
  • Acceptance criteria:
Scenario: Conversions
  Given the user enters "'5" in B1
  When the user enters "=B2+1" in A1
  And the user enters "=TRUE+1" in A2
  And the user enters "=""3""+1" in A3
  And the user enters "=B1*2" in A4
  And the user enters "=-B2" in A5
  And the user enters "=+""a""" in A6
  Then cell-A1 reads "1"
  And cell-A2 reads "2"
  And cell-A3 reads "#VALUE!"
  And cell-A4 reads "#VALUE!"
  And cell-A5 reads "0"
  And cell-A6 reads "#VALUE!"

FR-FML-05 Concatenation

  • Statement: The system shall evaluate & by converting both operands to text (02, section 2.7.3) and joining them: a number gives its general text whatever the format of any cell, a logical value gives TRUE or FALSE, blank gives the empty text.
  • Rationale: Labels are built from values.
  • Verification: Test
  • Acceptance criteria:
Scenario: Joining
  Given the user enters "0.5" in B1
  And the user clicks cell B1
  And the user sets the format to "percent1"
  When the user enters "=""a""&1.50&TRUE&B2" in A1
  And the user enters "=1/3&""""" in A2
  And the user enters "=B1&"" rate""" in A3
  And the user enters "=1&2+3" in A4
  Then cell-B1 reads "50.0%"
  And cell-A1 reads "a1.5TRUE"
  And cell-A2 reads "0.333333" and has data-kind "text"
  And cell-A3 reads "0.5 rate"
  And cell-A4 reads "15"

FR-FML-06 Comparison

  • Statement: The system shall evaluate =, <>, <, <=, > and >= as 02, section 2.7.6 states: a blank operand takes the type of the other one, texts are compared without regard to letter case, and across types any number is less than any text, which is less than any logical value.
  • Rationale: Every pair of values can be compared, with one result.
  • Verification: Test
  • Acceptance criteria:
Scenario: Same type and across types
  When the user enters "=""abc""=""ABC""" in A1
  And the user enters "=1<2<3" in A2
  And the user enters "=B1=0" in A3
  And the user enters "=B1=""""" in A4
  And the user enters "=B1=FALSE" in A5
  And the user enters "=1=""1""" in A6
  And the user enters "=10<""9""" in A7
  And the user enters "=""z""<TRUE" in A8
  And the user enters "=""ab""<""abc""" in A9
  And the user enters "=B1=B2" in A10
  Then cell-A1 reads "TRUE"
  And cell-A2 reads "FALSE"
  And cell-A3, cell-A4 and cell-A5 read "TRUE"
  And cell-A6 reads "FALSE"
  And cell-A7, cell-A8, cell-A9 and cell-A10 read "TRUE"

FR-FML-07 Cell references

  • Statement: The system shall evaluate a reference inside the grid to the value of its cell, blank for an empty cell, the $ signs having no effect on the value. If a reference is outside the grid, then the system shall give #REF!. If a range stands anywhere but as a range argument of a function that accepts ranges, then the system shall give #VALUE!. When the expression of a formula evaluates to blank, the value of the cell shall be the number 0.
  • Rationale: A formula reads other cells; a missing cell is an error and an empty one is not.
  • Verification: Test
  • Acceptance criteria:
Scenario: References
  Given the user enters "4" in B1
  When the user enters "=$B$1+b1" in A1
  And the user enters "=I1" in A2
  And the user enters "=A13+1" in A3
  And the user enters "=B1:B2" in A4
  And the user enters "=B5" in A5
  And the user enters "=(B1:B2)+1" in A6
  Then cell-A1 reads "8"
  And cell-A2 reads "#REF!"
  And cell-A3 reads "#REF!"
  And cell-A4 reads "#VALUE!"
  And cell-A5 reads "0" and has data-kind "number"
  And cell-A6 reads "#VALUE!"

FR-FML-08 Error propagation

  • Statement: When an operand of an operator is an error, the system shall give that error as the result of the operator, the error of the left operand when both are errors, and shall check this before any type rule (02, section 2.7.2). When both operands fail their conversion, the system shall give the error of the left operand.
  • Rationale: The first cause of a failure is the one shown.
  • Verification: Test
  • Acceptance criteria:
Scenario: Left first, errors before types
  When the user enters "=1/0+foo" in A1
  And the user enters "=foo+1/0" in A2
  And the user enters "=""a""+1/0" in A3
  And the user enters "=""a""&1/0" in A4
  And the user enters "=(1/0)=(1/0)" in A5
  Then cell-A1 reads "#DIV/0!"
  And cell-A2 reads "#NAME?"
  And cell-A3 reads "#DIV/0!"
  And cell-A4 reads "#DIV/0!"
  And cell-A5 reads "#DIV/0!"

FR-FML-09 Numeric errors

  • Statement: If a division has a divisor of 0, then the system shall give #DIV/0!. If a power has a base of 0 and an exponent of 0, or a negative base and an exponent that is not an integer, then the system shall give #NUM!; if it has a base of 0 and a negative exponent, then the system shall give #DIV/0!.
  • Rationale: An operation without a result says why.
  • Verification: Test
  • Acceptance criteria:
Scenario: Division and power
  When the user enters "=5/0" in A1
  And the user enters "=0^0" in A2
  And the user enters "=0^-1" in A3
  And the user enters "=(-8)^(1/3)" in A4
  And the user enters "=(-2)^3" in A5
  And the user enters "=2^0.5" in A6
  Then cell-A1 reads "#DIV/0!"
  And cell-A2 reads "#NUM!"
  And cell-A3 reads "#DIV/0!"
  And cell-A4 reads "#NUM!"
  And cell-A5 reads "-8"
  And cell-A6 reads "1.414214"

FR-FML-10 Circular references

  • Statement: The system shall give the value #CYCLE! to every circular cell and only to circular cells, as 02, section 2.9 defines them: a cell that can be reached from itself through the references and ranges of valid formulas, including those in arguments that are not evaluated. A cell that is not circular shall be evaluated normally, reading #CYCLE! as an error value from the circular cells it refers to. When a change of the sheet breaks a cycle, the cells that are no longer circular shall be evaluated normally.
  • Rationale: A loop has no result, and it is shown where it is, not everywhere downstream.
  • Verification: Test
  • Acceptance criteria:
Scenario: Loop, dependents, break
  When the user enters "=B1+1" in A1
  And the user enters "=A1+1" in B1
  And the user enters "=A1+1" in C1
  And the user enters "=IFERROR(A1,5)" in D1
  And the user enters "=IF(FALSE,E1,1)" in E1
  And the user enters "=SUM(A2:F2)" in F2
  Then cell-A1, cell-B1, cell-E1 and cell-F2 read "#CYCLE!"
  And cell-C1 reads "#CYCLE!"
  And cell-D1 reads "5"
  When the user enters "10" in B1
  Then cell-A1 reads "11"
  And cell-C1 reads "12"
  And cell-D1 reads "11"

FR-FML-11 Recalculation

  • Statement: When the raw content of a cell changes, by any action of this specification, the system shall show at once the new value of every cell whose value depends on it, directly or through other cells.
  • Rationale: The sheet is always consistent with its contents.
  • Verification: Test
  • Acceptance criteria:
Scenario: Chain
  Given the user enters "=A1*2" in B1
  And the user enters "=B1+1" in C1
  And the user enters "=SUM(A1:C1)" in D1
  When the user enters "5" in A1
  Then cell-B1 reads "10"
  And cell-C1 reads "11"
  And cell-D1 reads "26"
  When the user enters "x" in A1
  Then cell-B1 reads "#VALUE!"
  And cell-C1 reads "#VALUE!"
  And cell-D1 reads "#VALUE!"

5.2 Functions

FR-FUN-01 Function calls and arguments

  • Statement: The system shall recognize the 25 function names of 02, section 2.6.3 in any letter case. If the name of a call is not one of them, then the system shall give #NAME?. If the number of arguments is not allowed for the function, then the system shall give #ARGS!. These two checks shall be made in this order and before any argument is evaluated. The system shall then process the arguments in order and give the first error met, unless the function states otherwise (02, section 2.8.2).
  • Rationale: A wrong call is reported before its arguments are.
  • Verification: Test
  • Acceptance criteria:
Scenario: Name, count, then arguments
  When the user enters "=abs(-2)" in A1
  And the user enters "=FOO(1/0)" in A2
  And the user enters "=ABS(1/0,2)" in A3
  And the user enters "=ROUND(1)" in A4
  And the user enters "=MOD(foo,1/0)" in A5
  And the user enters "=NOT()" in A6
  Then cell-A1 reads "2"
  And cell-A2 reads "#NAME?"
  And cell-A3 reads "#ARGS!"
  And cell-A4 reads "#ARGS!"
  And cell-A5 reads "#NAME?"
  And cell-A6 reads "#ARGS!"

FR-FUN-02 SUM, AVERAGE, MIN, MAX

  • Statement: The system shall evaluate SUM, AVERAGE, MIN and MAX as 02, section 2.8.3 states: in a range argument (a single reference included) only number cells contribute and an error cell is an error met; a value argument is converted to number. AVERAGE without contribution shall give #DIV/0!; MIN and MAX without contribution shall give 0.
  • Rationale: Totals skip labels; a typed argument is not skipped.
  • Verification: Test
  • Acceptance criteria:
Scenario: Ranges and values
  Given the user enters "1" in A1
  And the user enters "x" in A2
  And the user enters "TRUE" in A3
  And the user enters "3" in A5

  And the user enters "=AVERAGE(A1:A5)" in B2

  And the user enters "=SUM(A2)" in B4
  And the user enters "=SUM(A2+0)" in B5
  And the user enters "=MAX(A2:A4)" in B6
  And the user enters "=AVERAGE(A2:A4)" in B7
  And the user enters "=MIN(A1:A5,-2)" in B8
  And the user enters "=SUM(""3"")" in B9
  Then cell-B1 reads "4"
  And cell-B2 reads "2"
  And cell-B3 reads "7"
  And cell-B4 reads "0"
  And cell-B5 reads "#VALUE!"
  And cell-B6 reads "0"
  And cell-B7 reads "#DIV/0!"
  And cell-B8 reads "-2"
  And cell-B9 reads "#VALUE!"

FR-FUN-03 COUNT and COUNTA

  • Statement: The system shall evaluate COUNT and COUNTA as 02, section 2.8.3 states: COUNT counts the number cells of its range arguments and its value arguments whose value is a number; COUNTA counts the cells of its range arguments that are not empty and each of its value arguments. An error cell or an error value is an error met.
  • Rationale: The user counts entries, numeric or not.
  • Verification: Test
  • Acceptance criteria:

FR-FUN-04 ROUND, ABS, INT, MOD

FR-FUN-05 IF

  • Statement: The system shall evaluate IF as 02, section 2.8.3 states: the first argument is converted to logical, and only the chosen one of the two other arguments is evaluated. The result may be blank.
  • Rationale: A branch that is not taken cannot fail.
  • Verification: Test
  • Acceptance criteria:
Scenario: Branches

  And the user enters "=IF(TRUE,B9,1)&""x""" in A5
  And the user enters "=IF(TRUE,B9,1)" in A6

  And cell-A4 reads "#DIV/0!"

FR-FUN-06 AND, OR, NOT

  • Statement: The system shall evaluate AND, OR and NOT as 02, section 2.8.3 states: every argument is evaluated and converted to logical in order, and the first error is the result, whatever the logical values before it.

FR-FUN-07 IFERROR, ISERROR, ISBLANK

FR-FUN-09 COUNTIF

  • Statement: The system shall evaluate COUNTIF with the steps of 02, section 2.8.3, in their order: the first argument shall be a range argument, the criterion gives an operator and an operand, empty cells never match, and a cell matches an ordering operator only when its value has the type of the operand.

FR-FUN-10 SUMIF
