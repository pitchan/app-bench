4. Functional requirements — Grid and editing

4.1 Grid

FR-GRD-01 Grid structure

  • Statement: The system shall show a grid of 8 columns A to H and 12 rows 1 to 12, with one col-header-<column> per column showing the column letter, one row-header-<row> per row showing the row number, and one cell-<address> per cell. The number of rows and columns shall never change. On a new sheet every cell shall be empty, with the format general.
  • Rationale: The sheet has a fixed size; rows and columns are inserted and deleted inside it.
  • Verification: Test
  • Acceptance criteria:
Scenario: New sheet
  When the page loads
  Then there are 96 cell elements, from cell-A1 to cell-H12
  And col-header-C reads "C"
  And row-header-12 reads "12"
  And every cell shows nothing and has data-kind "empty"

FR-GRD-02 Cell display

  • Statement: The system shall show in each cell the text of its value (02, section 2.5) and shall set data-kind to the type of that value. The system shall keep both up to date after every change of the sheet.
  • Rationale: A cell shows its result, never its formula.
  • Verification: Test
  • Acceptance criteria:
Scenario: Kinds
  When the user enters "12.50" in A1
  And the user enters "hello" in A2
  And the user enters "true" in A3
  And the user enters "=A1*2" in A4
  And the user enters "=1/0" in A5
  Then cell-A1 reads "12.5" and has data-kind "number"
  And cell-A2 reads "hello" and has data-kind "text"
  And cell-A3 reads "TRUE" and has data-kind "logical"
  And cell-A4 reads "25" and has data-kind "number"
  And cell-A5 reads "#DIV/0!" and has data-kind "error"
  And cell-A6 has data-kind "empty"

FR-GRD-03 Page frame

  • Statement: The system shall show one <header> element carrying data-testid="app-header" and one element carrying data-testid="toolbar" that contains the eleven toolbar controls, both visible at all times. format-select shall have exactly three <option> elements, in this order, with the values and texts of 03, section 3.2.
  • Rationale: The page has one place for its title and one for its actions.
  • Verification: Test
  • Acceptance criteria:
Scenario: Header, toolbar and formats
  When the page loads
  Then app-header is visible and is a header element
  And toolbar is visible and contains the ten buttons and format-select
  And the options of format-select have the values "general", "fixed2", "percent1"
  And the options of format-select have the texts "General", "1,234.50", "12.5%"

4.2 Selection

FR-SEL-01 Selecting with the pointer

  • Statement: When the user clicks a cell without the Shift key, the system shall make that cell the anchor and the active cell, and shall give the focus to grid. The system shall set aria-selected and data-in-selection on every cell as 03-ui-contract defines them. On a new sheet, the anchor and the active cell are A1. When grid receives the focus by any other means, the system shall change neither the selection, nor the sheet, nor the editing state.
  • Rationale: One cell is always active.
  • Verification: Test
  • Acceptance criteria:
Scenario: Click
  When the user clicks cell C4
  Then cell-C4 has aria-selected "true" and data-in-selection "true"
  And every other cell has aria-selected "false" and data-in-selection "false"
  And the grid has the focus

FR-SEL-02 Moving with the keyboard

  • Statement: When the user presses an arrow key without Shift on the grid, the system shall move the active cell by one cell in that direction and make it the anchor. If the active cell is already on the edge of the grid in that direction, the active cell shall not move and shall still become the anchor.
  • Rationale: The sheet is usable without a pointer.
  • Verification: Test
  • Acceptance criteria:
Scenario: Arrows
  Given the user clicks cell B2
  When the user presses ArrowRight on the grid
  And the user presses ArrowDown on the grid
  Then the selection is "C3"
  When the user clicks cell A1
  And the user presses ArrowUp on the grid
  Then the selection is "A1"

FR-SEL-03 Extending the selection

  • Statement: When the user shift-clicks a cell, the system shall make that cell the active cell, keep the anchor, and give the focus to grid. When the user presses an arrow key with Shift on the grid, the system shall move the active cell by one cell in that direction, when it is not on that edge of the grid, and keep the anchor. The selection is the rectangle between the anchor and the active cell.
  • Rationale: Clearing, copying and formatting act on rectangles.
  • Verification: Test
  • Acceptance criteria:
Scenario: Rectangle
  Given the user clicks cell D5
  When the user shift-clicks cell B2
  Then the selection is "B2:D5"
  And cell-B2 has aria-selected "true"
  And cell-D5 has aria-selected "false" and data-in-selection "true"
  And exactly 12 cells have data-in-selection "true"
  When the user presses Shift+ArrowRight on the grid
  Then the selection is "C2:D5"

FR-SEL-04 Name box

  • Statement: The system shall show in name-box the address of the active cell while the selection is one cell, and otherwise the address of the top-left cell of the selection, :, and the address of its bottom-right cell.
  • Rationale: The user reads where the selection is.
  • Verification: Test
  • Acceptance criteria:
Scenario: One cell and a rectangle
  When the user clicks cell H12
  Then name-box reads "H12"
  When the user shift-clicks cell A12
  Then name-box reads "A12:H12"

FR-SEL-05 Selection summary

  • Statement: While the selection holds one number cell at least (02, section 2.8.3), the system shall show selection-summary with TXT-01, where {n} is the number of number cells of the selection, {s} is the general text (02, section 2.5) of the normalized sum of their values, added in visiting order starting from 0, and {a} is the general text of that sum, before its normalization, divided by {n} and then normalized. The range rule of 02, section 2.4 applies to the final sum and to the average, each on its own, and not to the intermediate additions: when the normalized absolute value is 10^15 or more, {s} (or {a}) is written #NUM!. Cells of any other type, error cells included, are ignored. While the selection holds no number cell, selection-summary shall not be visible.
  • Rationale: The user checks a total without writing a formula.
  • Verification: Test
  • Acceptance criteria:
Scenario: Numbers, text and error
  Given the user enters "10" in A1
  And the user enters "x" in A2
  And the user enters "=1/0" in A3
  And the user enters "5" in A4
  When the user clicks cell A1
  And the user shift-clicks cell A4
  Then selection-summary reads "Sum: 15 | Average: 7.5 | Count: 2"
  When the user clicks cell A2
  Then selection-summary is not visible

Scenario: Sum out of range
  Given the user enters "999999999999000" in A1
  And the user enters "999999999999000" in A2
  When the user clicks cell A1
  And the user shift-clicks cell A2
  Then selection-summary reads "Sum: #NUM! | Average: 999999999999000 | Count: 2"

4.3 Editing

FR-EDT-01 Formula bar content

  • Statement: While the system is not in the editing state (FR-EDT-02), the value of formula-input shall be the raw content of the active cell, kept up to date when the active cell changes and when its raw content changes. When the user presses Enter on the grid, the system shall give the focus to formula-input without changing the selection.
  • Rationale: The cell shows the result; the formula bar shows what was typed.
  • Verification: Test
  • Acceptance criteria:
Scenario: Raw content
  Given the user enters "= a1 + 1" in B1
  And the user enters "007" in B2
  And the user enters "'=x" in B3
  When the user clicks cell B1
  Then formula-input has the value "=A1+1"
  When the user clicks cell B2
  Then formula-input has the value "007"
  And cell-B2 reads "7"
  When the user clicks cell B3
  Then formula-input has the value "'=x"
  And cell-B3 reads "=x"

FR-EDT-02 Editing state

  • Statement: When formula-input receives an input event while the system is not in the editing state, the system shall enter the editing state. While in the editing state, the system shall set data-editing="true" on formula-input and shall disable every toolbar control. While not in the editing state, data-editing shall be "false". The editing state ends only with a commit (FR-EDT-03) or a cancel (FR-EDT-04); formula-input losing the focus neither commits nor cancels. While in the editing state, the cells shall keep showing the sheet as it was before the edit. While in the editing state, a key of 03, section 3.3 pressed while grid has the focus shall change neither the sheet, nor the selection, nor the history, nor the clipboard, nor the editing state, nor the value of formula-input; preventDefault() is still called on its keydown event. The only effect kept is that of Enter, which gives the focus to formula-input (FR-EDT-01).
  • Rationale: Nothing changes in the sheet until the user confirms, and no other action mixes with a half-typed content.
  • Verification: Test
  • Acceptance criteria:
Scenario: Typing
  Given the user clicks cell A1
  When the user fills formula-input with "42"
  Then formula-input has data-editing "true"
  And every toolbar control is disabled
  And cell-A1 shows nothing

FR-EDT-03 Committing an edit

  • Statement: When the user presses Enter or Tab in formula-input, the system shall, in this order: (1) if in the editing state, commit the value of formula-input to the active cell under 02, section 2.2, and leave the editing state; (2) move the active cell by one row down for Enter, by one column right for Tab, and make it the anchor; if the active cell is already on that edge of the grid (row 12 for Enter, column H for Tab), the active cell shall not move and shall still become the anchor; (3) keep the focus in formula-input, which shows the raw content of the new active cell. When the user clicks or shift-clicks a cell while in the editing state, the system shall first commit as in (1), then apply FR-SEL-01 or FR-SEL-03. If the raw content that the commit would store equals the raw content of the cell, the commit shall change nothing and shall create no history step.
  • Rationale: Entering a column of values takes one key per value.
  • Verification: Test
  • Acceptance criteria:
Scenario: Enter and Tab
  Given the user clicks cell B2
  When the user fills formula-input with "1"
  And the user presses Enter in formula-input
  Then cell-B2 reads "1"
  And the selection is "B3"
  And formula-input has the focus and data-editing "false"
  When the user fills formula-input with "2"
  And the user presses Tab in formula-input
  Then cell-B3 reads "2"
  And the selection is "C3"

Scenario: Enter on the last row
  Given the user clicks cell A1
  And the user shift-clicks cell A12
  When the user fills formula-input with "5"
  And the user presses Enter in formula-input
  Then cell-A12 reads "5"
  And the selection is "A12"

Scenario: Click commits
  Given the user clicks cell A1
  When the user fills formula-input with "5"
  And the user clicks cell D4
  Then cell-A1 reads "5"
  And the selection is "D4"

FR-EDT-04 Cancelling an edit

  • Statement: When the user presses Escape in formula-input, the system shall leave the editing state without changing any cell, show again the raw content of the active cell in formula-input, and give the focus to grid.
  • Rationale: A typing mistake is dropped with one key.
  • Verification: Test
  • Acceptance criteria:
Scenario: Escape
  Given the user enters "8" in A1
  And the user clicks cell A1
  When the user fills formula-input with "99"
  And the user presses Escape in formula-input
  Then cell-A1 reads "8"
  And formula-input has the value "8" and data-editing "false"
  And the grid has the focus
  And undo-button is enabled and redo-button is disabled

FR-EDT-05 Content kinds

  • Statement: When a string is committed, the system shall decide its kind, its raw content and its value by the rules of 02, section 2.2, in the order given there.
  • Rationale: What is a number and what is a text is decided by one written rule.
  • Verification: Test
  • Acceptance criteria:
Scenario: Numbers and texts
  When the user enters " 12.5% " in A1
  And the user enters "1." in A2
  And the user enters "'12" in A3
  And the user enters " abc " in A4
  And the user enters "+.5" in A5
  And the user enters "'" in A6
  Then cell-A1 reads "0.125" and has data-kind "number"
  And cell-A2 reads "1." and has data-kind "text"
  And cell-A3 reads "12" and has data-kind "text"
  And cell-A4 has data-kind "text" and the raw content of A4 is " abc "
  And cell-A5 reads "0.5" and has data-kind "number"
  And cell-A6 shows nothing and has data-kind "text"

FR-EDT-06 Clearing cells

  • Statement: When the user clicks clear-button, or presses Delete or Backspace on the grid, the system shall set the raw content of every cell of the selection to the empty string. The formats and the selection shall not change. If every cell of the selection is already empty, nothing shall change and no history step shall be created.
  • Rationale: A block of cells is emptied in one action.
  • Verification: Test
  • Acceptance criteria:
Scenario: Clear a rectangle
  Given the user enters "1" in A1
  And the user enters "2" in B2
  And the user enters "=A1+B2" in C1
  When the user clicks cell A1
  And the user shift-clicks cell B2
  And the user presses Delete on the grid
  Then cell-A1 and cell-B2 show nothing
  And cell-C1 reads "0"
  And the selection is "A1:B2"

4.4 Numbers and formats

FR-NUM-01 Number normalization

  • Statement: The system shall normalize every number as 02, section 2.4 states: entry numbers, number literals, the result of every arithmetic operator and the result of every function that returns a number. If a result is not finite or reaches 10^15 in absolute value, then the system shall give #NUM!.
  • Rationale: The same sheet gives the same digits everywhere, and binary rounding noise never shows.
  • Verification: Test
  • Acceptance criteria:
Scenario: Twelve significant digits
  When the user enters "=0.1+0.2=0.3" in A1
  And the user enters "=1/3*3*1000000" in A2
  And the user enters "=1/3*3=1" in A3
  And the user enters "=123456789012345+0" in A4
  And the user enters "=999999999999999+1" in A5
  And the user enters "=10^15" in A6
  Then cell-A1 reads "TRUE"
  And cell-A2 reads "999999.999999"
  And cell-A3 reads "FALSE"
  And cell-A4 reads "123456789012000"
  And cell-A5 reads "#NUM!"
  And cell-A6 reads "#NUM!"

FR-NUM-02 General number display

  • Statement: The system shall show a number of a cell whose format is general as 02, section 2.5 states: rounded to 6 decimal places on its decimal representation, ties away from zero, without trailing zeros, without exponent, and without sign when the result is zero.
  • Rationale: Numbers are short to read and rounded the way people round.
  • Verification: Test
  • Acceptance criteria:
Scenario: General display
  When the user enters "=1.0000005" in A1
  And the user enters "=0.0000004" in A2
  And the user enters "=-0.0000004" in A3
  And the user enters "=2/3" in A4
  And the user enters "=1000000*1000000" in A5
  And the user enters "=0.1+0.7" in A6
  Then cell-A1 reads "1.000001"
  And cell-A2 reads "0"
  And cell-A3 reads "0"
  And cell-A4 reads "0.666667"
  And cell-A5 reads "1000000000000"
  And cell-A6 reads "0.8"

FR-NUM-03 Cell formats

  • Statement: When the user chooses a format in format-select, the system shall give that format to every cell of the selection and shall show the numbers of these cells in that format (02, section 2.5). While not in the editing state, format-select shall show the format of the active cell. The format shall belong to the cell, whatever its content: it is kept when the content changes or is cleared. If every cell of the selection already has the chosen format, no history step shall be created.
  • Rationale: Amounts and rates are read in their usual writing.
  • Verification: Test
  • Acceptance criteria:
Scenario: Fixed and percent
  Given the user enters "1234.565" in A1
  And the user enters "-0.004" in A2
  And the user enters "0.285" in B1
  And the user enters "abc" in B2
  When the user clicks cell A1
  And the user shift-clicks cell A2
  And the user sets the format to "fixed2"
  Then cell-A1 reads "1,234.57"
  And cell-A2 reads "0.00"
  When the user clicks cell B1
  And the user shift-clicks cell B2
  And the user sets the format to "percent1"
  Then cell-B1 reads "28.5%"
  And cell-B2 reads "abc"
  When the user clicks cell A1
  Then format-select has the value "fixed2"
  When the user enters "0.125" in A1
  Then cell-A1 reads "0.13"
