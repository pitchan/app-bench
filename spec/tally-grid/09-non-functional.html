9. Non-functional requirements

NFR-PKG-01 Single file delivery

  • Statement: The system shall be delivered as one file named index.html, starting with <!DOCTYPE html>, containing all of its HTML, CSS, JavaScript and SVG inline.
  • Rationale: The page opens directly from the file system with no installation.
  • Verification: Test
  • Acceptance criteria:
Scenario: Opened from disk
  When index.html is opened through a file:// URL
  Then the grid is usable

NFR-NET-01 No network access

  • Statement: The system shall not issue any network request (scripts, stylesheets, fonts, images, data) other than loading index.html itself.
  • Rationale: The page works offline and loads instantly.
  • Verification: Test
  • Acceptance criteria:
Scenario: No request
  When the page loads and the user enters values and formulas
  Then no request other than the page itself was made

NFR-DLG-01 No native dialogs

  • Statement: The system shall not call window.alert, window.confirm or window.prompt.
  • Rationale: Every message has its place in the sheet.
  • Verification: Test
  • Acceptance criteria:
Scenario: No dialog in any flow
  When the user performs every flow of this specification
  Then no native dialog is opened

NFR-ERR-01 No script errors

  • Statement: The system shall not throw any uncaught exception nor leave any rejected promise unhandled, from page load and during every flow of this specification, whatever string is committed to a cell. Every test of this specification fails when the page throws such an error during that test.
  • Rationale: A script error stops the page halfway; what still works afterwards is not a working page.
  • Verification: Test
  • Acceptance criteria:
Scenario: Clean run
  When the page loads and the user performs every flow of this specification
  Then the page threw no uncaught error

Scenario: Hostile contents
  When the user enters "=((((((((((" in A1
  And the user enters "=""" in A2
  And the user enters "=SUM(A1:H12)" in A3
  And the user enters "<b>bold</b>" in A4
  Then the page threw no uncaught error
  And cell-A4 reads "<b>bold</b>"

NFR-A11Y-01 Native controls and accessible names

  • Statement: The system shall use native <button>, <select> and <input> elements for every control of 03-ui-contract, with the accessible names given there, so that each control can be found by its role and exact accessible name. Disabled controls shall use the disabled attribute.
  • Rationale: Controls work with assistive technologies and the keyboard.
  • Verification: Test
  • Acceptance criteria:
Scenario: Roles and names
  When the page loads
  Then there is exactly one button named "Insert row"
  And there is exactly one button named "Undo", and it is disabled
  And there is exactly one combobox named "Number format"
  And there is exactly one textbox named "Cell content"

NFR-A11Y-02 Grid semantics

  • Statement: The system shall expose the sheet as a grid: one element with role="grid" and the accessible name Sheet, that can receive the focus; 13 elements with role="row" inside it (the row of column headers and the 12 rows); 8 elements with role="columnheader", 12 with role="rowheader" and 96 with role="gridcell", each inside its row; aria-selected="true" on the active cell only. These counts are the same whether the elements are counted by their explicit role attribute or by their computed accessibility role (Playwright getByRole) inside grid; a corner element (03, section 3.2) is counted in none of them.
  • Rationale: Assistive technologies can read the rows, the columns and which cell is selected.
  • Verification: Test
  • Acceptance criteria:
Scenario: Roles
  When the page loads
  Then there is exactly one grid named "Sheet"
  And the grid contains 13 rows, 8 column headers, 12 row headers and 96 grid cells
  And exactly one grid cell has aria-selected "true", and it is cell-A1
