1. How to read this specification

Read every file in this folder before writing code. The files are ordered:

File Content

02-values-and-formulas.md Glossary, cell contents, values, number normalization, display formats, formula language, evaluation rules, functions, reference rewriting
03-ui-contract.md Page structure, mandatory data-testid values, attributes, accessible names, fixed texts
04-fr-grid-and-editing.md Functional requirements: grid, selection, formula bar, entering and clearing content, number display
05-fr-formulas.md Functional requirements: formula language, errors, circular references, functions
06-fr-structure-and-clipboard.md Functional requirements: inserting and deleting rows and columns, copy, cut, paste

The visual design (colors, fonts, spacing, layout, decoration) is left to the implementer, within the limits of 08-rendering.

2. Conventions

2.1 Requirement keywords

Keyword Meaning
shall Mandatory.
shall not Mandatory prohibition.
may Permitted, left to the implementer.

Every requirement in this document is mandatory. There are no "should" requirements.

2.2 Requirement identifiers

<TYPE>-<AREA>-<NN>, for example FR-FML-03.

Part Values
TYPE FR functional, DR design and rendering, NFR non-functional
AREA GRD grid, SEL selection, EDT editing, NUM numbers and formats, FML formula language, FUN functions, STR rows and columns, CLP clipboard, HIS history, LAY fit and reachability, FOC focus, CON contrast, ANI animation, PKG packaging, NET network, DLG dialogs, ERR script errors, A11Y accessibility
NN Two-digit sequence number inside the area

Backticks mark literal values, to be used exactly as written: data-testid values such as formula-input (all listed in 03-ui-contract.md), error codes such as #REF!, function names such as SUMIF, and exact displayed texts.

Rules of 02-values-and-formulas.md are referenced by their section number, for example "02, section 2.6".

2.3 Requirement template

Each requirement has:

  • Statement — EARS sentences. Patterns used:
    • Ubiquitous: The system shall …
    • Event-driven: When , the system shall …
    • State-driven: While , the system shall …
    • Unwanted behavior: If , then the system shall …
  • Rationale — why the requirement exists.
  • Verification — always Test: executed in a browser against the delivered page.
  • Acceptance criteria — Gherkin scenarios. They illustrate the statement and are not the cases checked: the page is checked on many other sheets, formulas and sequences of actions, with values computed from the rules of 02-values-and-formulas. The statement and the rules are the reference.

2.4 Precedence

  1. The requirement statement.
  2. The definitions of files 02 and 03.
  3. The acceptance criteria.

Where this specification is silent (layout, colors, fonts, icons, decoration), the implementer decides. Where it is explicit, the implementation shall follow it exactly and shall not add behavior that changes it. This sheet is not a clone of an existing spreadsheet product: where a rule of this specification differs from what such a product does, this specification is the reference.

2.5 Verification conventions

Every requirement is verified in Chromium driven by Playwright. These conventions define the words used in the acceptance criteria.

Term Meaning
visible The element is in the DOM, its bounding box has a non-zero width and height, and its computed visibility is visible (Playwright toBeVisible).
not visible, hidden The element is not visible in the sense above (Playwright toBeHidden): it is absent, or its bounding box has a zero width or a zero height (for example through display: none on it or an ancestor, the hidden attribute, or empty content without padding or border), or its computed visibility is not visible. opacity: 0, transparent colors, clipping or off-screen positioning shall not be used to hide a conditional element.
text, reads, shows The element's text content with leading and trailing whitespace removed. For a cell, the text content of the cell-<address> element. A cell that shows nothing has an empty text content.
the raw content of X The value of formula-input after the user clicks cell X.
the user clicks cell X The grid container is scrolled so that the cell can receive the click, then a pointer click is made at the center of cell-X. With "shift-clicks", the Shift key is held during the click.
the user enters "v" in X The user clicks cell X, fills formula-input with v (the field's value is replaced by v and an input event is dispatched; no change event is guaranteed), then presses the Enter key while formula-input has the focus.
the user presses K on the grid The key K is pressed while the grid element has the focus. When the grid does not have the focus, the focus is first given to it with element.focus() on grid; no cell is clicked.
the user moves the focus with Tab to X On a page in the state the scenario sets, the focus is first given to grid with element.focus() (no cell is clicked), then Shift+Tab is pressed repeatedly until X has the focus. Shift+Tab is never handled by the page (03, section 3.3), so every control that is not disabled is reached whatever the order of the elements in the document. For X = grid, Shift+Tab is pressed repeatedly starting from a page that has just been loaded, until grid has the focus.
the user clicks button X The window is scrolled so that the element can receive the click (DR-LAY-02), then a pointer click is made at the center of the element.
clicking a disabled button Performed without Playwright's actionability checks (force: true); the check is that nothing changes.
the user sets the format to F The user selects the option with value F in format-select (Playwright selectOption, which dispatches input and change events).
the selection is R name-box reads R.
a read Every value is read once the page is settled: every animation and transition returned by document.getAnimations() that has a finite iteration count has finished, and the DOM does not change over two animation frames. Animations with an infinite iteration count are ignored (DR-ANI-01).
"say ""hi""" in a Gherkin string Gherkin strings are written between double quotes; a " character inside the string is doubled. The text of the example is say "hi".
a new sheet The page has just been loaded: every cell is empty, the selection is A1, the history is empty, the clipboard is empty.

Every scenario starts on a new sheet unless it states otherwise.
