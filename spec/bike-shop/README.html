Read every file in this folder before writing code. The files are ordered:

File Content

2. Conventions

2.1 Requirement keywords

Keyword Meaning
shall Mandatory.
shall not Mandatory prohibition.
may Permitted, left to the implementer.

Every requirement in this document is mandatory. There are no "should" requirements.

2.2 Requirement identifiers

<TYPE>-<AREA>-<NN>, for example FR-OPT-03.

Part Values
TYPE FR functional, DR design and rendering, NFR non-functional
AREA FIT rider and frame, OPT options and compatibility, UND undo, LIN order lines, PRM promo code, AMT order amounts, DLV delivery, CHK checkout, LAY fit and reachability, FOC focus, CON contrast, ANI animation, PKG packaging, NET network, DLG dialogs, ERR script errors, A11Y accessibility
NN Two-digit sequence number inside the area

Messages are referenced by MSG-<NN> and defined once, in 03-ui-contract.md.

Backticks mark literal values, to be used exactly as written: data-testid values such as add-to-order (all listed in 03-ui-contract.md), option ids and promo codes such as pro or TEAM15 (defined in 02-catalog-and-rules.md), and exact displayed texts such as Included. A backticked value is a data-testid only where 03-ui-contract.md lists it as one.

2.3 Requirement template

Each requirement has:

  • Statement — EARS sentences. Patterns used:
    • Ubiquitous: The system shall …
    • Event-driven: When , the system shall …
    • State-driven: While , the system shall …
    • Unwanted behavior: If , then the system shall …
  • Rationale — why the requirement exists.
  • Verification — always Test: executed in a browser against the delivered page.
  • Acceptance criteria — Gherkin scenarios. They illustrate the statement and are not the cases checked: the page is checked on many other configurations, orders and dates, with values computed from the rules of 02-catalog-and-rules. The statement and the rules are the reference.

2.4 Precedence

  1. The requirement statement.
  2. The definitions of files 02 and 03.
  3. The acceptance criteria.

Where this specification is silent (layout, colors, fonts, icons, copy not listed in the UI contract, decoration), the implementer decides. Where it is explicit, the implementation shall follow it exactly and shall not add behavior that changes it.

2.5 Verification conventions

Every requirement is verified in Chromium driven by Playwright. These conventions define the words used in the acceptance criteria.

Term Meaning
visible The element is in the DOM, its bounding box has a non-zero width and height, and its computed visibility is visible (Playwright toBeVisible).
not visible, hidden The element is not visible in the sense above (Playwright toBeHidden): it is absent, or its bounding box has a zero width or a zero height (for example through display: none on it or an ancestor, the hidden attribute, or empty content without padding or border), or its computed visibility is not visible. opacity: 0, transparent colors, clipping or off-screen positioning keep a non-zero box and therefore do not make an element not visible; they shall not be used to hide a conditional element.
text, reads The element's text content with leading and trailing whitespace removed, and every run of whitespace inside it replaced by one space.
the user fills X with "v" The field's value is replaced by v and an input event is dispatched. The field keeps the focus; no change event is guaranteed. Every reaction to typing shall therefore run on the input event.
the user selects card X, clicks card X, clicks button X The window is scrolled so that the element can receive the click (DR-LAY-02), then a pointer click is made at the center of the element.
the user checks / unchecks "name" The user clicks the accessory card whose input has that accessible name, only when the checkbox is not already in the requested state. The input itself is never the click target.
the user applies "v" The user fills promo-input with v and clicks promo-apply.
clicking a disabled card or button Performed without Playwright's actionability checks (force: true); the check is that nothing changes.
the user adds a bike "…" The user fills height-input with a valid height, clicks the option cards that give the listed choices and the quantity buttons that give the listed quantity, then clicks add-to-order. Options not listed keep their values.
now is D T The browser clock is set to local date D and local time T before the page loads (page.clock). Without a time, T is 10:00.
a read Every value is read once the page is settled: every animation and transition returned by document.getAnimations() that has a finite iteration count has finished, and the DOM does not change over two animation frames. Animations with an infinite iteration count are ignored (DR-ANI-01).
"29\" wheels" in a Gherkin string \" stands for one " character (U+0022). The text is 29" wheels.
