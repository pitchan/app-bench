4. Functional requirements — Configurator

4.1 Rider and frame

FR-FIT-01 Height field and validation

  • Statement: The system shall treat the content of height-input as a valid height when, after removing leading and trailing whitespace, it consists only of the digits 0 to 9 and its value is from 150 to 200. While the content is not empty after that removal and is not a valid height, the system shall show height-error with MSG-01. While the height is valid, the system shall show height-recommendation with MSG-02 for the recommended frame. The system shall react on every input event of the field.
  • Rationale: Frames are sized from the rider's height; a wrong value is pointed out as it is typed.
  • Verification: Test
  • Acceptance criteria:
Scenario: Valid and invalid heights
  When the user fills height-input with "149"
  Then height-error reads "Enter a height between 150 and 200 cm."
  And height-recommendation is not visible
  When the user fills height-input with " 168 "
  Then height-error is not visible
  And height-recommendation reads "Recommended frame: M"
  When the user fills height-input with ""
  Then height-error is not visible
  And height-recommendation is not visible

FR-FIT-02 Frame recommendation

  • Statement: While the height is valid, the system shall show the [data-role="badge"] of the card of the recommended frame, and only that one. While the height is not valid, no badge shall be visible.
  • Rationale: The customer sees which size fits, whatever frame is selected.
  • Verification: Test
  • Acceptance criteria:
Scenario: Badge follows the height
  When the user fills height-input with "184"
  Then the badge of card-frame-L is visible
  And the badges of card-frame-S, card-frame-M and card-frame-XL are not visible

FR-FIT-03 Automatic frame mode

  • Statement: While automatic frame mode is on, when the height becomes valid or changes to another valid value, the system shall select the recommended frame; if this changes the selected frame (an automatic frame change), the system shall apply the cascades of 02-catalog-and-rules, section 2.3. When the height becomes not valid, the frame shall stay as it is. Automatic frame mode shall be on when the page loads and whenever the configurator is reset (FR-LIN-01, FR-LIN-06, FR-LIN-07, FR-CHK-04); it shall end when the user selects a frame card whose frame was not selected, and while a line is being edited (FR-LIN-05). Selecting the card of the frame already selected shall not end it.
  • Rationale: Most customers take the recommended size; one deliberate choice is enough to keep another one.
  • Verification: Test
  • Acceptance criteria:
Scenario: Frame follows the height until a manual choice
  When the user fills height-input with "170"
  Then the radio "Frame M" is checked
  When the user fills height-input with "190"
  Then the radio "Frame XL" is checked
  When the user selects card-frame-L
  And the user fills height-input with "160"
  Then the radio "Frame L" is checked

4.2 Options

FR-OPT-01 Option groups and defaults

  • Statement: The system shall display one option card per catalog option in its section, in catalog order, and whenever the configurator is reset (page load included) shall select 27.5" wheels, Essential 1×10 and Graphite, no accessory, quantity 1, and no frame unless automatic frame mode selects one.
  • Rationale: Every bike starts from the same cheapest configuration.
  • Verification: Test
  • Acceptance criteria:
Scenario: Defaults at load
  When the page loads
  Then the radios "27.5\" wheels", "Essential 1×10" and "Graphite" are checked
  And no frame radio is checked
  And no accessory checkbox is checked
  And qty-value reads "1"

FR-OPT-02 Card price text

  • Statement: The system shall show in the [data-role="price"] element of each card: for a frame, its price in amount format; for any other option, its surcharge or price in signed format (+€120.00, or Included when zero). The price of Racing Red shall read Included while Pro Electronic 2×12 is selected, and +€60.00 otherwise.
  • Rationale: Each card tells what it adds to the price of the bike.
  • Verification: Test
  • Acceptance criteria:
Scenario: Racing Red price follows the drivetrain
  When the user selects card-frame-L
  And the user selects card-drivetrain-pro
  Then the price of card-color-red reads "Included"
  And the price of card-wheels-29 reads "+€120.00"

FR-OPT-03 Unavailable options

  • Statement: While an option is unavailable under 02-catalog-and-rules, section 2.3, the system shall disable its input and show the [data-role="reason"] of its card with the reason of that table. While it is available, its input shall be enabled and its reason not visible. Clicking the card of an unavailable option shall change nothing.
  • Rationale: The customer sees at once what cannot be combined with the chosen frame, and why.
  • Verification: Test
  • Acceptance criteria:
Scenario: Frame XL and Glacier
  When the user selects card-frame-XL
  Then the radio "Glacier" is disabled
  And the reason of card-color-glacier reads "Available with frames M and L only"
  And the radio "Pro Electronic 2×12" is enabled

FR-OPT-04 Cascades

  • Statement: After each user action and each automatic frame change, the system shall apply the cascades of 02-catalog-and-rules, section 2.3, so that the bike configuration satisfies every constraint of that section. The system shall not change any option that no cascade names.
  • Rationale: The configuration never holds an impossible combination, and it changes only where a rule requires it.
  • Verification: Test
  • Acceptance criteria:
Scenario: Pro drivetrain brings 29-inch wheels
  When the user selects card-frame-M
  And the user selects card-drivetrain-pro
  Then the radio "29\" wheels" is checked
  When the user selects card-wheels-275
  Then the radio "Sport 1×12" is checked

FR-OPT-05 Notice

  • Statement: When a user action or an automatic frame change applies one cascade or more, the system shall show notice with the messages of these cascades, in the order of the cascade table, separated by one space. The notice shall keep that text until the next user action, the next automatic frame change, an undo, or a reset of the configurator; then it shall show the messages of that new event if it applied cascades, and otherwise it shall be hidden.
  • Rationale: The customer is told every change the system made, and only the latest ones.
  • Verification: Test
  • Acceptance criteria:
Scenario: Rack replaces the kickstand and adds mudguards
  When the user checks "Kickstand"
  And the user checks "Rear rack"
  Then notice reads "Mudguards were added: required by the rear rack. Kickstand was removed: not compatible with the rear rack."
  When the user checks "Lights"
  Then notice is not visible

FR-OPT-06 Quantity of the bike

  • Statement: When the user activates qty-increase or qty-decrease, the system shall add or subtract 1 to the quantity of the current bike and show it in qty-value. While the quantity is 1, qty-decrease shall be disabled; while it is 5, qty-increase shall be disabled.
  • Rationale: Several identical bikes are ordered in one step, within the workshop's batch size.
  • Verification: Test
  • Acceptance criteria:
Scenario: Quantity limits
  When the page loads
  Then qty-decrease is disabled
  When the user clicks qty-increase 4 times
  Then qty-value reads "5"
  And qty-increase is disabled

FR-OPT-07 Bike price

  • Statement: While a frame is selected, the system shall show in bike-price the unit price of the current bike configuration (02-catalog-and-rules, section 2.5) multiplied by its quantity, in amount format. While no frame is selected, bike-price shall read — (U+2014 EM DASH).
  • Rationale: The customer sees what the bike being configured costs before adding it.
  • Verification: Test
  • Acceptance criteria:
Scenario: Price of the current bike
  When the page loads
  Then bike-price reads "—"
  When the user selects card-frame-M
  And the user checks "Lights"
  And the user clicks qty-increase
  Then bike-price reads "€2,459.80"

4.3 Undo

FR-UND-01 Undo history

  • Statement: Before each user action that changes the bike configuration or the quantity, the system shall record in the undo history the frame, wheels, drivetrain, color, accessories, quantity and the state of automatic frame mode. A user action that changes nothing shall record nothing. Changes of the height field and automatic frame changes shall record nothing. The history shall be emptied whenever the configurator is reset and when an edit starts (FR-LIN-05). While the history is empty, undo-button shall be disabled.
  • Rationale: The customer can go back over any number of choices of the bike being configured.
  • Verification: Test
  • Acceptance criteria:
Scenario: Undo enabled by a choice
  When the page loads
  Then undo-button is disabled
  When the user selects card-color-sand
  Then undo-button is enabled

FR-UND-02 Undo action

  • Statement: When the user activates undo-button, the system shall restore the last recorded state exactly, cascaded options included, remove it from the history, hide notice, and leave the height field unchanged. Restoring a state shall not apply any cascade, and shall not select a frame, even while automatic frame mode is on: a restored state with no frame keeps no frame until the height changes or the user selects a frame card.
  • Rationale: One undo reverts one user action with everything the system changed with it.
  • Verification: Test
  • Acceptance criteria:
Scenario: Undo reverts a cascade
  When the user selects card-frame-M
  And the user selects card-drivetrain-pro
  And the user clicks undo-button
  Then the radio "Essential 1×10" is checked
  And the radio "27.5\" wheels" is checked
  And the radio "Frame M" is checked
  And undo-button is enabled
  When the user clicks undo-button
  Then no frame radio is checked
  And undo-button is disabled
