2. Conventions

2.1 Requirement keywords

Keyword Meaning
shall Mandatory.
shall not Mandatory prohibition.
may Permitted, left to the implementer.

Every requirement in this document is mandatory. There are no "should" requirements.

2.2 Requirement identifiers

<TYPE>-<AREA>-<NN>, for example FR-FIT-03.

Part Values
TYPE FR functional, DR design, NFR non-functional
AREA FIT rider and frame, OPT options, QTY quantity, PRM promo code, PRC price, SUM summary, DLV delivery, ORD order, TOK tokens, LAY layout, CMP components, STA states, THM theme, MOT motion, PKG packaging, NET network, DLG dialogs, A11Y accessibility
NN Two-digit sequence number inside the area

Messages are referenced by MSG-<NN> and defined once, in 03-ui-contract.md.

Backticks mark literal values, to be used exactly as written: data-testid values such as order-button (all listed in 03-ui-contract.md), option ids and promo codes such as pro or SPRING10 (defined in 02-catalog-and-rules.md), tokens starting with -- such as --color-accent (defined in 04-design-system.md), CSS selectors such as [data-role="price"], and exact displayed texts or CSS values such as Included or #C8102E. A backticked value is a data-testid only where 03-ui-contract.md lists it as one.

2.3 Requirement template

Each requirement has:

  • Statement — EARS sentences. Patterns used:
    • Ubiquitous: The system shall …
    • Event-driven: When , the system shall …
    • State-driven: While , the system shall …
    • Unwanted behavior: If , then the system shall …
  • Rationale — why the requirement exists.
  • Verification — always Test: executed in a browser against the delivered page.
  • Acceptance criteria — Gherkin scenarios. They illustrate the statement and are not the only cases checked. The statement is the reference.

2.4 Precedence

  1. The requirement statement.
  2. The definitions of files 02, 03 and 04.
  3. The acceptance criteria.

Where this specification is silent (copy not listed in the UI contract, icons, illustrations, decoration), the implementer decides. Where it is explicit, the implementation shall follow it exactly and shall not add behavior that changes it.

When two statements apply to the same element in the same state, the more specific one wins; in particular FR-PRC-03 (no frame selected) replaces the frame line and the amounts of FR-SUM-01.

2.5 Verification conventions

Every requirement is verified in Chromium driven by Playwright. These conventions define the words used in the acceptance criteria.

Term Meaning
visible The element is in the DOM, its bounding box has a non-zero width and height, and its computed visibility is visible (Playwright toBeVisible).
not visible, hidden The element is absent, or it or an ancestor has display: none (for example through the hidden attribute), or its computed visibility is hidden. opacity: 0, transparent colors, clipping or off-screen positioning do not make an element not visible, and shall not be used to hide a conditional element.
the user fills X with "v" The field's value is replaced by v and an input event is dispatched. The field keeps the focus; no change event is guaranteed. Every reaction to typing shall therefore run on the input event.
the user types "v" in X The characters of v are typed one by one with the keyboard, each producing an input event.
the user selects card X, clicks card X A pointer click at the center of the card.
the user checks / unchecks "name" A pointer click at the center of the accessory card whose input has that accessible name, made only when the checkbox is not already in the requested state. The hidden input itself is never the click target.
the user applies "v" The user fills promo-input with v and clicks promo-apply.
clicking or hovering a disabled card Performed without Playwright's actionability checks (force: true); the check is that nothing changes.
has property "value" The value returned by getComputedStyle for that property. A requirement written with a shorthand (border, outline, padding) is checked through its longhands (border-top-width, border-top-style, border-top-color, outline-width, outline-style, outline-color, padding-top…).
after a change Style values are read once every transition of the element has ended.
layout measurements Made in headless Chromium, where scrollbars take no width. Positions are in CSS pixels relative to the viewport, within 1 px.
today is D The browser clock is set to D before the page loads (page.clock).
the color scheme is light or dark Set with emulateMedia({ colorScheme }). Without that step the scheme is light.
reduced motion is requested Set with emulateMedia({ reducedMotion: 'reduce' }).
"29\" wheels" in a Gherkin string \" stands for one " character (U+0022). The text is 29" wheels.
the configuration of example Pn Built through the user interface with the choices listed in row Pn of 02-catalog-and-rules, section 2.7, and a valid height (178 unless stated otherwise).
