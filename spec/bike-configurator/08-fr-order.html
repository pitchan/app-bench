8. Functional requirements — Order

FR-ORD-01 Order button label

  • Statement: The system shall show in order-button the text MSG-14 for the current quantity.
  • Rationale: The customer sees how many bikes the click orders.
  • Verification: Test
  • Acceptance criteria:
Scenario: Singular and plural
  When the page loads
  Then order-button reads "Order 1 bike"
  When the user activates qty-increase
  Then order-button reads "Order 2 bikes"

FR-ORD-02 Order availability

  • Statement: While the height is not valid or no frame is selected, the system shall disable order-button. While the height is not valid, the system shall show order-hint with MSG-15. While the height is valid and a frame is selected, order-button shall be enabled and order-hint not visible.
  • Rationale: The workshop builds every frame to a known rider height.
  • Verification: Test
  • Acceptance criteria:
Scenario: Manual frame without height
  Given the user selected card-frame-M
  Then order-button is disabled
  And order-hint shows "Enter your height to continue."
  When the user fills height-input with "170"
  Then order-button is enabled and order-hint is not visible

FR-ORD-03 Order confirmation

  • Statement: When the user activates the enabled order-button, the system shall hide configurator and summary, hide notice, show confirmation with confirmation-title (MSG-16), confirmation-reference (MSG-17), confirmation-total (the summary total at the time of the order) and confirmation-delivery (the summary delivery date at the time of the order), and move keyboard focus to confirmation-title.
  • Rationale: The customer gets a clear end state and keyboard and screen-reader users land on it.
  • Verification: Test
  • Acceptance criteria:
Scenario: Confirm example P1
  Given today is 2026-11-13
  And the configuration of example P1 with height 178
  When the user activates order-button
  Then configurator and summary are not visible
  And confirmation-title shows "Order confirmed"
  And confirmation-reference shows "BK-20261113-001"
  And confirmation-total shows "€4,550.31"
  And confirmation-title has the keyboard focus

FR-ORD-04 Order reference

  • Statement: The system shall number confirmed orders from 1 when the page loads and add 1 at each confirmed order, and shall build confirmation-reference with MSG-17. A reload starts again at 1.
  • Rationale: Each order of a session has its own reference.
  • Verification: Test
  • Acceptance criteria:
Scenario: Second order
  Given today is 2026-11-13 and one order was confirmed
  When the user activates confirmation-new, configures a valid bike and activates order-button
  Then confirmation-reference shows "BK-20261113-002"

FR-ORD-05 New configuration

  • Statement: When the user activates confirmation-new, the system shall hide confirmation, show configurator and summary in their load-time state (empty height, automatic frame mode on, no frame, default options, no accessory, quantity 1, no applied code, empty promo-input, no error, no notice), and move keyboard focus to height-input. The order counter of FR-ORD-04 is kept.
  • Rationale: The next bike starts from a clean configuration.
  • Verification: Test
  • Acceptance criteria:
Scenario: Back to defaults
  Given an order was confirmed with quantity 3 and WELCOME50 applied
  When the user activates confirmation-new
  Then height-input is empty and has the keyboard focus
  And qty-value reads "1"
  And no frame radio is checked
  And promo-status is not visible
  When the user fills height-input with "190"
  Then the radio "Frame XL" is checked
