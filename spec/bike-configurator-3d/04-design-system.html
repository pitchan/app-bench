4. Design system

4.1 Tokens

Tokens are CSS custom properties declared on :root. Their names and values are fixed and shall be written exactly as in the tables below, letter case aside: #FFFFFF may be written #ffffff, but not #fff, white or rgb(255, 255, 255); 150ms shall not be written 0.15s.

Colors

Token Light theme Dark theme Use
--color-bg #F6F4F0 #121110 Page background
--color-surface #FFFFFF #1D1B19 Panels, cards, summary
--color-text #1B1A18 #F3F0EA Main text
--color-muted #67625B #A59F96 Secondary text, prices on cards, hover border
--color-border #DCD6CC #38342F Borders
--color-accent #0E6B58 #3BC4A5 Selection, primary button, focus ring, discounts
--color-accent-contrast #FFFFFF #0B0A09 Text on accent

--color-disabled-bg #ECE8E1 #2A2724 Background of a disabled primary button

The dark values apply while the media query (prefers-color-scheme: dark) matches (DR-THM-01).

4.2 How values are checked

Design requirements are checked on the rendered page with getComputedStyle and element bounding boxes. Consequences for the implementer:

  • A color requirement is met when the computed color equals the token value (computed colors are reported as rgb(...); #0E6B58 is rgb(14, 107, 88)).
  • A length requirement is met when the computed length equals the stated value in pixels.
  • A requirement written with a shorthand property (border, outline, padding) is checked through its longhands (README, section 2.5). Chromium serializes some shorthands in another order (outline reads rgb(14, 107, 88) solid 2px), so the shorthand string itself is never compared.
  • Visual effects that change the computed values listed in 09-dr-design (for example a semi-transparent overlay that changes a card's computed background) are not allowed.
  • The font family is free. Use a system font stack; no web font may be loaded (NFR-NET-01).
