6. Functional requirements — Options

FR-OPT-01 Option groups and defaults

  • Statement: The system shall display one option card per catalog option, grouped in section-frame, section-wheels, section-drivetrain, section-color and section-accessories, in catalog order, and when the page loads shall select 27.5" wheels, Essential 1×10 and Graphite, no frame and no accessory.
  • Rationale: Every configuration starts from the same cheapest complete bike.
  • Verification: Test
  • Acceptance criteria:
Scenario: Defaults
  When the page loads
  Then the radios "27.5\" wheels", "Essential 1×10" and "Graphite" are checked
  And no frame radio is checked
  And no accessory checkbox is checked
  And section-frame contains card-frame-S, card-frame-M, card-frame-L, card-frame-XL in that order

FR-OPT-02 Card price text

  • Statement: The system shall show in the [data-role="price"] element of each card: for a frame, its price in amount format; for any other option, its surcharge or price in signed format (+€120.00, or Included when zero); for Racing Red while the drivetrain is pro, MSG-06.
  • Rationale: Each card tells what it adds to the price.
  • Verification: Test
  • Acceptance criteria:
Scenario: Card prices
  When the page loads
  Then the price of card-frame-L reads "€1,240.00"
  And the price of card-wheels-275 reads "Included"
  And the price of card-wheels-29 reads "+€120.00"
  And the price of card-accessory-lights reads "+€39.90"
  And the price of card-color-red reads "+€60.00"
  When the user selects card-drivetrain-pro
  Then the price of card-color-red reads "Included with Pro"

FR-OPT-03 29-inch wheels and frame S

  • Statement: While frame S is selected, the system shall disable the input of card-wheels-29 and show its [data-role="reason"] with MSG-04. While another frame or no frame is selected, the input shall be enabled and the reason not visible.
  • Rationale: 29-inch wheels do not fit the small frame.
  • Verification: Test
  • Acceptance criteria:
Scenario: Disabled with frame S
  When the user selects card-frame-S
  Then the radio "29\" wheels" is disabled
  And the reason of card-wheels-29 reads "Not available with frame S"
  When the user selects card-frame-M
  Then the radio "29\" wheels" is enabled

FR-OPT-04 Wheel replacement cascade

  • Statement: When frame S becomes selected, by the user or by automatic frame mode, while 29" wheels are selected, the system shall select 27.5" wheels and show notice with MSG-07. Selecting another frame afterwards shall not select 29" wheels again.
  • Rationale: The configuration never holds an impossible combination, and the customer is told what changed.
  • Verification: Test
  • Acceptance criteria:
Scenario: Automatic frame triggers the cascade
  Given the user filled height-input with "180" and selected card-wheels-29
  When the user fills height-input with "158"
  Then the radio "Frame S" is checked
  And the radio "27.5\" wheels" is checked
  And notice shows "29\" wheels were replaced by 27.5\" wheels: not available with frame S."
  When the user fills height-input with "180"
  Then the radio "27.5\" wheels" is still checked

FR-OPT-05 Out-of-stock color

  • Statement: The system shall keep the input of card-color-glacier disabled at all times and show its [data-role="reason"] with MSG-05; Glacier shall not become selected by clicking its card or by keyboard navigation in the color group.
  • Rationale: An out-of-stock color is shown but cannot be ordered.
  • Verification: Test
  • Acceptance criteria:
Scenario: Glacier cannot be chosen
  When the user clicks card-color-glacier, without actionability checks (README 2.5)
  Then the radio "Graphite" is still checked
  And the reason of card-color-glacier reads "Out of stock"

Scenario: Arrow keys skip Glacier
  Given the radio "Racing Red" is checked and focused
  When the user presses ArrowRight
  Then the radio "Glacier" is not checked

FR-OPT-06 Racing Red with Pro drivetrain

  • Statement: While the drivetrain is pro, the system shall count the Racing Red surcharge as €0.00 in every price. The 3 extra business days of Racing Red shall still apply.
  • Rationale: Racing Red is the signature color of the Pro build.
  • Verification: Test
  • Acceptance criteria:
Scenario: Surcharge waived
  Given the user selected card-frame-M and card-color-red
  When the user selects card-drivetrain-pro
  Then the value of summary-line-color reads "Included"
  And the value of summary-line-unit reads "€1,880.00"

FR-OPT-07 Rack adds mudguards

  • Statement: When the user checks Rear rack while Mudguards is unchecked, the system shall check both and show notice with MSG-08. When Mudguards is already checked, checking Rear rack shall show no notice.
  • Rationale: The rack is mounted on the mudguard eyelets.
  • Verification: Test
  • Acceptance criteria:
Scenario: Mudguards added
  When the user checks "Rear rack"
  Then the checkboxes "Rear rack" and "Mudguards" are checked
  And notice shows "Mudguards were added: required by the rear rack."

FR-OPT-08 Mudguards removal removes rack

  • Statement: When the user unchecks Mudguards while Rear rack is checked, the system shall uncheck both and show notice with MSG-09. Unchecking Rear rack shall leave Mudguards unchanged.
  • Rationale: The dependency holds in both directions.
  • Verification: Test
  • Acceptance criteria:
Scenario: Rack removed with mudguards
  Given "Rear rack" and "Mudguards" are checked
  When the user unchecks "Mudguards"
  Then neither checkbox is checked
  And notice shows "Rear rack was removed: it requires mudguards."

Scenario: Removing the rack alone
  Given "Rear rack" and "Mudguards" are checked
  When the user unchecks "Rear rack"
  Then "Mudguards" is still checked

FR-OPT-09 Notice lifetime

  • Statement: The system shall keep notice hidden when the page loads. After a cascade shows it, the notice shall stay visible until the next configuration change made by the user (height content, any option, quantity), which shall hide it, or replace its text when that change causes a cascade of its own. The notice shall also be hidden by FR-ORD-03 and FR-ORD-05. Promo code actions shall not affect it. Activating an option that is already selected, including the frame re-activation of FR-FIT-05, is not a configuration change and leaves the notice unchanged.
  • Rationale: The customer reads the explanation of an automatic change at their own pace.
  • Verification: Test
  • Acceptance criteria:
Scenario: Notice cleared by the next change
  Given notice shows "Mudguards were added: required by the rear rack."
  When the user types "WELCOME50" in promo-input and activates promo-apply
  Then notice is still visible
  When the user checks "Lights"
  Then notice is not visible
