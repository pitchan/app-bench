5. Functional requirements — Rider and frame

FR-FIT-01 Height field

  • Statement: The system shall display height-input empty when the page loads, with no error, no recommendation, and no frame selected.
  • Rationale: The frame size depends on the rider; nothing is assumed before the customer says how tall they are.
  • Verification: Test
  • Acceptance criteria:
Scenario: Initial state
  When the page loads
  Then height-input is empty
  And height-error and height-recommendation are not visible
  And no frame radio is checked

FR-FIT-02 Height validation

  • Statement: On every input event of height-input (each keystroke, deletion or paste, without waiting for the field to lose focus), the system shall remove leading and trailing whitespace and consider the height valid only if the result consists of digits only and its value is from 150 to 200 inclusive. While that trimmed content is not empty and the height is not valid, the system shall show height-error with MSG-01. While the trimmed content is empty (for example "" or " "), no error shall be shown and the height is not valid.
  • Rationale: The frame table covers 150 to 200 cm; anything else cannot be fitted.
  • Verification: Test
  • Acceptance criteria:
Scenario Outline: Height values
  When the user fills height-input with "<input>"
  Then the height is "<state>"

  Examples:
    | input                         | state                                          |
    | 150                           | valid                                          |
    | 200                           | valid                                          |
    | 180 with one space on each side | valid                                        |
    | 149                           | error "Enter a height between 150 and 200 cm." |
    | 201                           | error "Enter a height between 150 and 200 cm." |
    | 17a                           | error "Enter a height between 150 and 200 cm." |
    | 175.5                         | error "Enter a height between 150 and 200 cm." |
    | empty string                  | not valid, no error shown                      |
    | three spaces                  | not valid, no error shown                      |

FR-FIT-03 Frame recommendation

  • Statement: While the height is valid, the system shall show height-recommendation with MSG-02 naming the recommended frame (02-catalog-and-rules, 2.3). While the height is not valid, height-recommendation shall not be visible.
  • Rationale: The customer sees which size fits before choosing.
  • Verification: Test
  • Acceptance criteria:
Scenario Outline: Range boundaries
  When the user fills height-input with "<height>"
  Then height-recommendation shows "Recommended frame: <size>"

  Examples:
    | height | size |
    | 164    | S    |
    | 165    | M    |
    | 174    | M    |
    | 175    | L    |
    | 185    | XL   |

FR-FIT-04 Automatic frame selection

  • Statement: While automatic frame mode is on, when the height becomes valid or changes to another valid value, the system shall select the recommended frame and apply the resulting cascades (FR-OPT-04). While the height is not valid, the system shall leave the frame selection unchanged.
  • Rationale: Most customers take the recommended size; they should not have to pick it themselves.
  • Verification: Test
  • Acceptance criteria:
Scenario: Frame follows the height
  When the user fills height-input with "178"
  Then the radio "Frame L" is checked
  When the user fills height-input with "160"
  Then the radio "Frame S" is checked

Scenario: Invalid height keeps the frame
  Given the user filled height-input with "178"
  When the user fills height-input with "17"
  Then the radio "Frame L" is still checked

FR-FIT-05 Manual frame selection

  • Statement: When the user selects a frame card, the system shall select that frame and end automatic frame mode; afterwards, height changes shall not change the selected frame. Activating the card of the frame that is already selected (click, tap, or Space on its focused radio) is a manual frame choice and also ends automatic frame mode. A frame may be selected before any height is entered.
  • Rationale: A customer who chose a size on purpose keeps it.
  • Verification: Test
  • Acceptance criteria:
Scenario: Manual choice is kept
  Given the user filled height-input with "178"
  When the user selects the card card-frame-XL
  And the user fills height-input with "160"
  Then the radio "Frame XL" is checked

Scenario: Confirming the recommended frame is a manual choice
  Given the user filled height-input with "178"
  When the user selects the card card-frame-L
  And the user fills height-input with "160"
  Then the radio "Frame L" is checked

FR-FIT-06 Recommended badge

  • Statement: While the height is valid, the system shall show the [data-role="badge"] element with the text Recommended in the card of the recommended frame only, whether automatic frame mode is on or not. While the height is not valid, no badge shall be visible.
  • Rationale: The recommendation stays visible after a manual choice.
  • Verification: Test
  • Acceptance criteria:
Scenario: Badge after a manual choice
  Given the user selected card-frame-XL
  When the user fills height-input with "160"
  Then the badge of card-frame-S is visible with the text "Recommended"
  And the badges of card-frame-M, card-frame-L and card-frame-XL are not visible

FR-FIT-07 Size gap warning

  • Statement: While the height is valid, a frame is selected, and the size gap between the selected frame and the recommended frame is 2 or more, the system shall show frame-warning with MSG-03, using larger when the selected frame comes after the recommended frame in size order and smaller otherwise. In every other state frame-warning shall not be visible.
  • Rationale: A frame two sizes off is almost always a mistake, but the customer may still order it.
  • Verification: Test
  • Acceptance criteria:
Scenario: Three sizes larger
  Given the user selected card-frame-XL
  When the user fills height-input with "160"
  Then frame-warning shows "Frame XL is 3 sizes larger than recommended."

Scenario: One size off is not warned
  Given the user selected card-frame-XL
  When the user fills height-input with "180"
  Then frame-warning is not visible

Scenario: Two sizes smaller
  Given the user selected card-frame-S
  When the user fills height-input with "176"
  Then frame-warning shows "Frame S is 2 sizes smaller than recommended."
