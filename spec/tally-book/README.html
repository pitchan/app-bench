Tally Book — Software Requirements Specification

Field Value
Document Software Requirements Specification (SRS)
Product Tally Book, a spreadsheet workbook of up to five sheets, with formulas
Version 1.0
Status Approved for implementation
Structure Adapted from ISO/IEC/IEEE 29148:2018, clause 9.6 (SRS content)
Requirement syntax EARS (Easy Approach to Requirements Syntax)
Acceptance criteria Gherkin (Given / When / Then)

1. How to read this specification

Read every file in this folder before writing code. The files are ordered:

File Content
01-product-overview.md Purpose, scope, user, operating environment, constraints
02-values-and-formulas.md Glossary, cell contents, values, number normalization, display formats, formula language, evaluation rules, functions, reference rewriting, dates, sheet names, defined names, sorting order, series, finding, CSV text
03-ui-contract.md Page structure, mandatory data-testid values, attributes, accessible names, fields, messages, fixed texts
04-fr-grid-and-editing.md Functional requirements: grid, selection, formula bar, entering and clearing content, number display
05-fr-formulas.md Functional requirements: formula language, errors, references to other sheets, circular references, functions, dates
06-fr-structure-and-clipboard.md Functional requirements: inserting and deleting rows and columns, copy, cut, paste, within a sheet and across sheets
07-fr-history.md Functional requirements: undo and redo
08-rendering.md Rendering requirements: fit, reachability, focus, contrast, animation
09-non-functional.md Non-functional requirements: packaging, network, dialogs, script errors, accessibility
10-fr-sheets-and-names.md Functional requirements: sheets (tabs, adding, renaming, deleting, switching), defined names
11-fr-sort-fill-find-csv.md Functional requirements: sorting, filling, finding and replacing, CSV export and import
12-fr-persistence.md Functional requirements: saving and restoring the workbook

Files 10 to 12 are functional requirements like files 04 to 07; they come after file 09 only to keep the numbers of the other files.

The visual design (colors, fonts, spacing, layout, decoration) is left to the implementer, within the limits of 08-rendering. The technology is left to the implementer too, within 09-non-functional: one self-contained index.html.

2. Conventions

2.1 Requirement keywords

Keyword Meaning
shall Mandatory.
shall not Mandatory prohibition.
may Permitted, left to the implementer.

Every requirement in this document is mandatory. There are no "should" requirements.

2.2 Requirement identifiers

<TYPE>-<AREA>-<NN>, for example FR-FML-03.

Part Values
TYPE FR functional, DR design and rendering, NFR non-functional
AREA GRD grid, SEL selection, EDT editing, NUM numbers and formats, FML formula language, FUN functions, DAT dates, STR rows and columns, CLP clipboard, HIS history, SHT sheets, NAM defined names, SRT sort, FIL fill, FND find and replace, CSV CSV text, PER persistence, LAY fit and reachability, FOC focus, CON contrast, ANI animation, PKG packaging, NET network, DLG dialogs, ERR script errors, A11Y accessibility
NN Two-digit sequence number inside the area

Backticks mark literal values, to be used exactly as written: data-testid values such as formula-input (all listed in 03-ui-contract.md), error codes such as #REF!, function names such as SUMIF, and exact displayed texts.

Rules of 02-values-and-formulas.md are referenced by their section number, for example "02, section 2.6".

2.3 Requirement template

Each requirement has:

  • Statement — EARS sentences. Patterns used:
    • Ubiquitous: The system shall …
    • Event-driven: When , the system shall …
    • State-driven: While , the system shall …
    • Unwanted behavior: If , then the system shall …
  • Rationale — why the requirement exists.
  • Verification — always Test: executed in a browser against the delivered page.
  • Acceptance criteria — Gherkin scenarios. They illustrate the statement and are not the cases checked: the page is checked on many other workbooks, formulas and sequences of actions, with values computed from the rules of 02-values-and-formulas. The statement and the rules are the reference.

2.4 Precedence

  1. The requirement statement.
  2. The definitions of files 02 and 03.
  3. The acceptance criteria.

Where this specification is silent (layout, colors, fonts, icons, decoration), the implementer decides. Where it is explicit, the implementation shall follow it exactly and shall not add behavior that changes it. This workbook is not a clone of an existing spreadsheet product: where a rule of this specification differs from what such a product does (the calendar of 1900, the lookups on lists that are not sorted, the default of VLOOKUP, the closed set of TEXT patterns, the formulas moved by a sort, and others), this specification is the reference.

2.5 Verification conventions

Every requirement is verified in Chromium driven by Playwright. These conventions define the words used in the acceptance criteria.

Term Meaning
visible The element is in the DOM, its bounding box has a non-zero width and height, and its computed visibility is visible (Playwright toBeVisible). An element that carries a data-testid shall not use display: contents: such an element has no box of its own, and Playwright would report it visible through its children.
not visible, hidden The element is not visible in the sense above (Playwright toBeHidden): it is absent, or its bounding box has a zero width or a zero height (for example through display: none on it or an ancestor, the hidden attribute, or empty content without padding or border), or its computed visibility is not visible. opacity: 0, transparent colors, clipping or off-screen positioning shall not be used to hide a conditional element.
text, reads, shows The element's text content with leading and trailing whitespace removed. For a cell, the text content of the cell-<address> element. A cell that shows nothing has an empty text content.
cell X, cell-X The cell of address X in the active sheet, and the element that shows it.
the raw content of X The value of formula-input after the user clicks cell X.
the user clicks cell X The grid container is scrolled so that the cell can receive the click, then a pointer click is made at the center of cell-X. With "shift-clicks", the Shift key is held during the click.
the user enters "v" in X The user clicks cell X, fills formula-input with v, then presses the Enter key while formula-input has the focus.
the user fills F with "v" The value of the field F is replaced by v (Playwright fill). When v is not empty, no key is pressed and one input event is dispatched, even when v equals the previous value. When v is the empty string, the content of the field is selected and the Delete key is pressed in the field: an input event is dispatched only if the field was not empty. No change event is guaranteed. F is formula-input, sheet-name-input, name-input, find-input, replace-input or csv-text.
the user checks C, the user unchecks C A pointer click is made on the checkbox C when its state is not the one asked (Playwright check, uncheck).
X is checked, X is not checked The checked property of the checkbox X.
F has the value "v" The value property of the field F is exactly v. For csv-text, the line breaks of that value are LF characters.
a text between """ lines A text of several lines (Gherkin doc string). Its lines are joined with one LF, after removing from each line the indentation of the opening """; there is no LF after its last line. A last line that is empty therefore stands for a text that ends with a line break. Inside a doc string, " characters are written once, not doubled.
the user presses K on the grid The key K is pressed while the grid element has the focus. When the grid does not have the focus, the focus is first given to it with element.focus() on grid; no cell is clicked.
the user moves the focus with Tab to X On a page in the state the scenario sets, the focus is first given to grid with element.focus() (no cell is clicked), then Shift+Tab is pressed repeatedly until X has the focus. Shift+Tab is never handled by the page (03, section 3.3), so every control that is not disabled is reached whatever the order of the elements in the document. For X = grid, on a page that has just been loaded, document.activeElement.blur() is first called, so that no element has the focus whatever the page did on load; then Shift+Tab is pressed at least once, and repeatedly until grid has the focus.
X looks different from its unfocused state The six properties of DR-FOC-01 are read on X twice: once while another element, or no element, has the focus (for X = grid, just after the blur() call above; for any other X, just after the focus has been given to grid), and once after the last Shift+Tab press. At least one of the six values differs. For grid or cell-A1, both elements are read both times and a difference on either one is enough.
the user clicks button X The window is scrolled so that the element can receive the click (DR-LAY-02), then a pointer click is made at the center of the element. "N times": the click is made N times, a read being possible after each.
the user clicks sheet tab N The user clicks button sheet-tab-N.
clicking a disabled button Performed without Playwright's actionability checks (force: true); the check is that nothing changes.
the user sets the format to F The user selects the option with value F in format-select (Playwright selectOption, which dispatches input and change events).
the user renames the sheet to "v" The user fills sheet-name-input with v, then clicks button rename-sheet.
the user defines the name "v", the user deletes the name "v" The user fills name-input with v, then clicks button define-name, or button delete-name. The selection is the one the scenario has set.
the selection is R name-box reads R.
the active sheet is S Exactly one sheet tab has aria-selected="true", and it reads S.
there are N sheet tabs The elements sheet-tab-1 to sheet-tab-N exist and are visible, and there is no sheet-tab-<N+1>.
there are N name items The elements name-item-1 to name-item-N exist and are visible, and there is no name-item-<N+1>. "No name items": there is no name-item-1.
X is enabled, X is disabled The control X does not carry, or carries, the disabled attribute.
the user reloads the page The page is loaded again at the same address (Playwright page.reload); localStorage is kept as the page left it.
localStorage holds "v" under the key "k" Before the scripts of the page run, the key k of localStorage is set to the string v, and every other key is removed.
localStorage is unavailable Before the scripts of the page run, Storage.prototype.getItem, setItem and removeItem are replaced by functions that throw a DOMException.
a read Every value is read once the page is settled: every animation and transition returned by document.getAnimations() that has a finite iteration count has finished, and the DOM does not change over two animation frames. Animations with an infinite iteration count are ignored (DR-ANI-01).
"say ""hi""" in a Gherkin string Gherkin strings are written between double quotes; a " character inside the string is doubled. The text of the example is say "hi".
a new workbook The page has just been loaded in a browser whose localStorage holds no key tally-book: one sheet named Sheet1, every cell empty, the selection A1, no defined name, the history empty, the clipboard empty, the fields and the messages as 03, sections 3.4 and 3.5 state for a load.

Every scenario starts on a new workbook unless it states otherwise. In a scenario, the cells, the selection and the actions are those of the active sheet at that moment.
