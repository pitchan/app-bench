12. Functional requirements — Persistence

The workbook is kept in the localStorage of the browser, under one key: tally-book. The format of the value stored under that key is free. A new workbook is what the page shows when it loads and finds nothing it can restore: one sheet named Sheet1, every cell empty with the format general, the selection A1, no defined name.

FR-PER-01 Saving the workbook

  • Statement: After every action that changes the workbook (the sheets, their order and their names, the raw content or the format of a cell, the defined names and their targets), the active sheet, or the anchor or the active cell of a sheet, undo and redo included, the system shall store the whole state in localStorage under the key tally-book, before it handles the next user action, so that a reload at any moment restores the state the user last saw. The whole saved state shall be the value of that single key: the system shall write no other key in localStorage, and shall keep no state in sessionStorage, in cookies or in any other storage. A content that is being typed and is not committed (FR-EDT-02) is not part of the state.
  • Rationale: Closing the page loses nothing, and one key is all there is to remove to start again.
  • Verification: Test
  • Acceptance criteria:
Scenario: Saved at once
  Given the user enters "42" in B2
  And the user clicks cell D4
  When the user reloads the page
  Then cell-B2 reads "42"
  And the selection is "D4"
  And localStorage has exactly one key, "tally-book"
  When the user enters "43" in B2
  And the user clicks button undo-button
  And the user reloads the page
  Then cell-B2 reads "42"
  And the selection is "B2"

FR-PER-02 Restoring the workbook

  • Statement: When the page loads and localStorage holds, under the key tally-book, a state that the page stored, the system shall restore it: the sheets in their order, with their names, the raw content and the format of every cell, the anchor and the active cell of each sheet; the active sheet; the defined names, in their writing, with their targets, the removed ones included. The raw contents shall be restored as they were stored, without being committed again (02, section 2.2): no formula is written again and no format is changed. Every value shall then be computed from the restored contents, and every element of the page shall show the restored state.
  • Rationale: The user finds the workbook exactly as it was left: same sheet, same selection, same names.
  • Verification: Test
  • Acceptance criteria:
Scenario: The whole workbook comes back
  Given the user enters "=sheet2!A1+1" in A3
  And the user clicks button add-sheet
  And the user enters "7" in A1
  And the user clicks sheet tab 1
  And the user enters "1234.5" in A1
  And the user enters "2024-02-29" in A2
  And the user clicks cell A1
  And the user sets the format to "fixed2"
  And the user shift-clicks cell A2
  And the user defines the name "Data"
  And the user renames the sheet to "Main book"
  And the user clicks sheet tab 2
  And the user enters "=SUM(Data)" in B1
  And the user clicks cell C3
  And the user shift-clicks cell D5
  When the user reloads the page
  Then there are 2 sheet tabs
  And sheet-tab-1 reads "Main book"
  And sheet-tab-2 reads "Sheet2"
  And sheet-tab-2 has aria-selected "true"
  And sheet-name-input has the value "Sheet2"
  And the selection is "C3:D5"
  And cell-B1 reads "46584.5"
  And name-item-1 reads "Data = 'Main book'!A1:A2"
  When the user clicks sheet tab 1
  Then the selection is "A1:A2"
  And cell-A1 reads "1,234.50"
  And cell-A2 reads "2024-02-29"
  And cell-A3 reads "8"
  And the raw content of A3 is "=sheet2!A1+1"
  When the user clicks cell A2
  Then format-select has the value "date"

In this scenario A3 was committed before Sheet2 existed and is stored =sheet2!A1+1; the reload restores that exact string.

FR-PER-03 What is not saved

  • Statement: When the page loads, whatever it restores, the system shall start with: an empty history (undo-button and redo-button disabled); an empty clipboard (paste-button disabled); no editing state; no visible message (sheet-message, name-message, find-status, csv-message); and the fields of 03, section 3.4 in their starting state: name-input, find-input, replace-input and csv-text empty, find-case, find-whole and csv-raw unchecked, sheet-name-input holding the name of the active sheet.
  • Rationale: A reload brings back the data, not the gestures in progress.
  • Verification: Test
  • Acceptance criteria:
Scenario: History, clipboard, fields and messages
  Given the user enters "5" in A1
  And the user clicks cell A1
  And the user clicks button copy-button
  And the user fills find-input with "5"
  And the user fills replace-input with "6"
  And the user checks find-case
  And the user clicks button find-next
  And the user clicks button csv-export
  And the user fills name-input with "Rate2"
  And the user clicks button define-name
  And the user fills formula-input with "zzz"
  When the user reloads the page
  Then cell-A1 reads "5"
  And formula-input has the value "5"
  And formula-input has data-editing "false"
  And undo-button is disabled
  And redo-button is disabled
  And paste-button is disabled
  And find-input has the value ""
  And replace-input has the value ""
  And find-case is not checked
  And find-status is not visible
  And csv-text has the value ""
  And name-input has the value ""
  And name-message is not visible

FR-PER-04 Unusable saved data

  • Statement: If, when the page loads, the key tally-book is absent, or its value is not a complete state that the page stored — for example the empty string, {not json, null, [], {}, 0, {"sheets":[]} or any other string the page cannot read back as a whole workbook — then the system shall start a new workbook, without any uncaught error and without showing a message. The system shall then save normally at the next change. If reading or writing localStorage throws an exception, then the system shall work as specified in everything else, without persistence and without any uncaught error.
  • Rationale: Damaged or foreign data never blocks the page; the worst case is an empty workbook.
  • Verification: Test
  • Acceptance criteria:
Scenario: Damaged data
  Given localStorage holds "{not json" under the key "tally-book"
  When the page loads
  Then there is 1 sheet tab
  And sheet-tab-1 reads "Sheet1"
  And every cell shows nothing
  And the selection is "A1"
  And there are no name items
  And the page threw no uncaught error
  When the user enters "1" in A1
  And the user reloads the page
  Then cell-A1 reads "1"

Scenario: Storage that throws
  Given localStorage is unavailable
  When the page loads
  And the user enters "=1+1" in A1
  And the user clicks button add-sheet
  Then there are 2 sheet tabs
  And the page threw no uncaught error
  When the user clicks sheet tab 1
  Then cell-A1 reads "2"
