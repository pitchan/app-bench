6. Functional requirements — Rows, columns and clipboard

6.1 Rows and columns

The four actions below act on the active sheet, on the row or the column of its active cell, whatever the selection. They never change the selection: the anchor and the active cell keep their addresses. The cells of the other sheets do not move; their formulas are rewritten when they point to the active sheet (FR-STR-05).

FR-STR-01 Inserting a row or a column

  • Statement: When the user clicks insert-row, the system shall, without changing the selection, for r the row of the active cell: move the raw content and the format of every cell of rows r to 11 one row down, drop the contents and formats of row 12, and make every cell of row r empty with the format general. When the user clicks insert-col, the system shall do the same with columns: for c the column of the active cell, the cells of columns c to G move one column right, column H is dropped and column c becomes empty with the format general.
  • Rationale: Room is made inside a sheet of fixed size; what is pushed out is lost.
  • Verification: Test
  • Acceptance criteria:
Scenario: Insert a row
  Given the user enters "top" in A1
  And the user enters "mid" in A2
  And the user enters "last" in A12
  And the user clicks cell A2
  And the user sets the format to "fixed2"
  When the user clicks button insert-row
  Then cell-A1 reads "top"
  And cell-A2 shows nothing
  And cell-A3 reads "mid"
  And cell-A12 shows nothing
  And the selection is "A2"
  And format-select has the value "general"
  When the user clicks cell A3
  Then format-select has the value "fixed2"

FR-STR-02 Deleting a row or a column

  • Statement: When the user clicks delete-row, the system shall, without changing the selection, for r the row of the active cell: drop the contents and formats of row r, move the raw content and the format of every cell of rows r + 1 to 12 one row up, and make every cell of row 12 empty with the format general. When the user clicks delete-col, the system shall do the same with columns: column c is dropped, the cells of the columns after c move one column left, and column H becomes empty with the format general.
  • Rationale: A row or a column is removed without leaving a hole.
  • Verification: Test
  • Acceptance criteria:
Scenario: Delete a column
  Given the user enters "a" in A1
  And the user enters "b" in B1
  And the user enters "c" in C1
  And the user enters "h" in H1
  And the user clicks cell B5
  When the user clicks button delete-col
  Then cell-A1 reads "a"
  And cell-B1 reads "c"
  And cell-G1 reads "h"
  And cell-H1 shows nothing
  And the selection is "B5"

FR-STR-03 References after an insertion

  • Statement: When a row or a column is inserted, the system shall rewrite the valid formulas as 02, section 2.10.1 states, and store them in canonical form: references to the cells that moved follow them, $ signs included; a reference pushed out of the grid becomes #REF!; a range grows when the insertion is inside it and is cut at the edge of the grid.
  • Rationale: A formula keeps pointing at the same data after the data moved.
  • Verification: Test
  • Acceptance criteria:
Scenario: Row inserted at row 3
  Given the user enters "=A2+A3" in C1
  And the user enters "=$A$12" in C2
  And the user enters "=SUM(A1:A12)" in D1
  And the user enters "=SUM(A3:B12)" in D2
  And the user enters "=SUM(A12:B12)" in E1
  And the user enters "=C1+1" in E5
  And the user enters "=Z9+A40" in F1
  And the user clicks cell H3
  When the user clicks button insert-row
  Then the raw content of C1 is "=A2+A4"
  And the raw content of C2 is "=#REF!"
  And cell-C2 reads "#REF!"
  And the raw content of D1 is "=SUM(A1:A12)"
  And the raw content of D2 is "=SUM(A4:B12)"
  And the raw content of E1 is "=SUM(#REF!)"
  And the raw content of E6 is "=C1+1"
  And the raw content of F1 is "=Z9+A40"

Scenario: Column inserted at column B
  Given the user enters "=B1+$G$1+H1" in A2
  And the user enters "=SUM(A1:H1)" in A3
  And the user clicks cell B7
  When the user clicks button insert-col
  Then the raw content of A2 is "=C1+$H$1+#REF!"
  And the raw content of A3 is "=SUM(A1:H1)"

FR-STR-04 References after a deletion

  • Statement: When a row or a column is deleted, the system shall rewrite the valid formulas as 02, section 2.10.2 states, and store them in canonical form: a reference to a deleted cell becomes #REF!; references to the cells that moved follow them; a range shrinks when the deletion is inside it and becomes #REF! when nothing of it remains.
  • Rationale: A formula that lost its data says so; the others keep pointing at theirs.
  • Verification: Test
  • Acceptance criteria:
Scenario: Row 3 deleted
  Given the user enters "=A2+A4" in C1
  And the user enters "=A3*2" in C2
  And the user enters "=SUM(A1:A5)" in D1
  And the user enters "=SUM(A3:B3)" in D2
  And the user enters "=SUM(A3:A4)" in E1
  And the user enters "=SUM($A$4:A$6)" in E2
  And the user clicks cell B3
  When the user clicks button delete-row
  Then the raw content of C1 is "=A2+A3"
  And the raw content of C2 is "=#REF!*2"
  And cell-C2 reads "#REF!"
  And the raw content of D1 is "=SUM(A1:A4)"
  And the raw content of D2 is "=SUM(#REF!)"
  And the raw content of E1 is "=SUM(A3:A3)"
  And the raw content of E2 is "=SUM($A$3:A$5)"

FR-STR-05 References from other sheets

  • Statement: When a row or a column is inserted or deleted in a sheet, the system shall rewrite, in every valid formula of every sheet of the workbook, the references and ranges that point to that sheet (02, section 2.10): those that have a sheet prefix naming it, wherever they are, and those without prefix in its own formulas. The system shall leave unchanged every reference that points to another sheet or to no sheet, in particular the references without prefix of the other sheets, even when they have the same address. Each sheet prefix shall be kept as it is stored; a reference that is removed becomes #REF! with its prefix removed.
  • Rationale: A formula of another sheet keeps pointing at the same data, and a formula that never looked at the changed sheet is not touched.
  • Verification: Test
  • Acceptance criteria:
Scenario: Row inserted in Sheet2
  Given the user enters "=A3+Sheet2!A3+SUM(sheet2!A1:A5)+Other!A3" in C1
  And the user enters "=Sheet2!$A$12+Sheet2!B3" in C2
  And the user clicks button add-sheet
  And the user enters "=A3+Sheet1!A3+Sheet2!A12" in C1
  And the user enters "5" in A3
  And the user clicks cell H3
  When the user clicks button insert-row
  Then the raw content of C1 is "=A4+Sheet1!A3+#REF!"
  And cell-A4 reads "5"
  When the user clicks sheet tab 1
  Then the raw content of C1 is "=A3+Sheet2!A4+SUM(sheet2!A1:A6)+Other!A3"
  And the raw content of C2 is "=#REF!+Sheet2!B4"
  And cell-C1 reads "#REF!"

Scenario: Column deleted in Sheet1
  Given the user enters "1" in A1
  And the user enters "2" in B1
  And the user enters "3" in C1
  And the user enters "=B1+C1" in D1
  And the user clicks button add-sheet
  And the user enters "=Sheet1!B1+Sheet1!C1+B1" in A2
  And the user enters "=SUM(Sheet1!A1:C1)" in A3
  And the user enters "=SUM(Sheet1!B1:B2)" in A4
  And the user enters "=SUM(B1:B2)" in A5
  When the user clicks sheet tab 1
  And the user clicks cell B5
  And the user clicks button delete-col
  Then the raw content of C1 is "=#REF!+B1"
  When the user clicks sheet tab 2
  Then the raw content of A2 is "=#REF!+Sheet1!B1+B1"
  And the raw content of A3 is "=SUM(Sheet1!A1:B1)"
  And cell-A3 reads "4"
  And the raw content of A4 is "=SUM(#REF!)"
  And the raw content of A5 is "=SUM(B1:B2)"

6.2 Clipboard

The clipboard is internal to the page, and there is one for the whole workbook. It is empty when the page loads: on a new workbook and after every reload (FR-PER-03). It holds one block: the raw contents and the formats of the cells of a rectangle, as they were when the block was taken, the address of that rectangle, the name that the sheet of that rectangle had when the block was taken, and a mode, copy or cut. Later changes of the workbook do not change the block (FR-CLP-05). The history (file 07) does not change the clipboard.

FR-CLP-01 Copy and paste

  • Statement: When the user clicks copy-button, the system shall put in the clipboard the block of the selection, in mode copy, and shall change nothing in the sheet. When the user clicks paste-button with a block in mode copy, the system shall write the block in the active sheet, with its top-left cell on the top-left cell of the selection: each cell of the block gives its raw content (adjusted for valid formulas, FR-CLP-02) and its format to the cell at the same offset; the cells of the block that fall outside the grid are dropped; an empty cell of the block makes its destination empty. The system shall then make the top-left cell of the destination both the anchor and the active cell. The clipboard shall keep its block, which can be pasted again. While the clipboard is empty, the system shall disable paste-button.
  • Rationale: A block of cells is repeated elsewhere, any number of times.
  • Verification: Test
  • Acceptance criteria:
Scenario: Copy a block twice
  Given the user enters "1" in A1
  And the user enters "x" in B1
  And the user enters "0.5" in A2
  And the user clicks cell A2
  And the user sets the format to "percent1"
  And the user enters "old" in D2
  When the user clicks cell A1
  And the user shift-clicks cell B2
  And the user clicks button copy-button
  And the user enters "9" in A1
  And the user clicks cell C1
  And the user clicks button paste-button
  Then cell-C1 reads "1"
  And cell-D1 reads "x"
  And cell-C2 reads "50.0%"
  And cell-D2 shows nothing
  And the selection is "C1"
  When the user clicks cell H12
  And the user clicks button paste-button
  Then cell-H12 reads "1"
  And cell-A1 reads "9"

FR-CLP-02 Reference adjustment on paste

  • Statement: When a block in mode copy is pasted, the system shall adjust each valid formula of the block as 02, section 2.10.3 states, by the offset between the cell it was copied from and the cell it is written to, and store it in canonical form: parts without $ move, parts with $ do not, a reference that leaves the grid becomes #REF!, a range with a corner that leaves the grid becomes #REF! as a whole. Formulas that are not valid and contents that are not formulas shall be written unchanged.
  • Rationale: A copied formula does the same calculation at its new place.
  • Verification: Test
  • Acceptance criteria:
Scenario: From B2 to D5 and to A1
  Given the user enters "=A1+$A1+A$1+$A$1" in B2
  When the user clicks cell B2
  And the user clicks button copy-button
  And the user clicks cell D5
  And the user clicks button paste-button
  Then the raw content of D5 is "=C4+$A4+C$1+$A$1"
  When the user clicks cell A1
  And the user clicks button paste-button
  Then the raw content of A1 is "=#REF!+#REF!+#REF!+$A$1"

Scenario: Ranges
  Given the user enters "=SUM(A1:$B2)" in B2
  And the user enters "=SUM(A1:G1)" in B3
  And the user enters "=1+" in B4
  When the user clicks cell B2
  And the user shift-clicks cell B4
  And the user clicks button copy-button
  And the user clicks cell D5
  And the user clicks button paste-button
  Then the raw content of D5 is "=SUM($B4:C5)"
  And the raw content of D6 is "=SUM(#REF!)"
  And the raw content of D7 is "=1+"

FR-CLP-03 Cut and paste

  • Statement: When the user clicks cut-button, the system shall put in the clipboard the block of the selection, in mode cut, and shall change nothing in the sheet. When the user clicks paste-button with a block in mode cut, the system shall, in this order: (1) make every cell of the rectangle the block was taken from empty, with the format general, in the sheet that has the name recorded in the block (FR-CLP-05); (2) write the block in the active sheet as FR-CLP-01 states for a block in mode copy (same destination, cells outside the grid dropped, formats written, an empty cell of the block makes its destination empty), its formulas unchanged (no adjustment), then make the top-left cell of the destination both the anchor and the active cell; (3) empty the clipboard. The formulas of the other cells of the workbook shall not be rewritten, and the targets of the defined names shall not change.
  • Rationale: A block of cells is moved as it is.
  • Verification: Test
  • Acceptance criteria:
Scenario: Move a block
  Given the user enters "5" in A1
  And the user enters "=A1*2" in A2
  And the user enters "=A2+1" in C1
  When the user clicks cell A1
  And the user shift-clicks cell A2
  And the user clicks button cut-button
  Then cell-A1 reads "5"
  When the user clicks cell A2
  And the user clicks button paste-button
  Then cell-A1 shows nothing
  And cell-A2 reads "5"
  And the selection is "A2"
  And the raw content of A3 is "=A1*2"
  And cell-A3 reads "0"
  And the raw content of C1 is "=A2+1"
  And cell-C1 reads "6"
  And paste-button is disabled

Scenario: Paste on a selection of several cells
  Given the user enters "5" in A1
  When the user clicks cell A1
  And the user clicks button cut-button
  And the user clicks cell C1
  And the user shift-clicks cell D4
  And the user clicks button paste-button
  Then cell-C1 reads "5"
  And the selection is "C1"

FR-CLP-04 Clipboard across sheets

  • Statement: The system shall keep one clipboard for the whole workbook: a block taken in one sheet can be pasted in any sheet, and switching sheets shall not change the clipboard. When a block in mode copy is pasted, the system shall adjust its valid formulas by the offset between the addresses of the source cell and of the destination cell (02, section 2.10.3), whatever their sheets: a reference without sheet prefix then names a cell of the sheet it is pasted in; a reference with a sheet prefix keeps its prefix and moves in the same way. When a block in mode cut is pasted in another sheet, the system shall empty the rectangle it was taken from in its own sheet (FR-CLP-03) and write the formulas unchanged.
  • Rationale: Cells are copied and moved from one sheet to another with the rules of one sheet.
  • Verification: Test
  • Acceptance criteria:
Scenario: Copy to another sheet
  Given the user enters "10" in A1
  And the user enters "=A1*2+Sheet1!A1+Sheet1!$A$1" in B2
  And the user clicks cell B2
  And the user clicks button copy-button
  And the user clicks button add-sheet
  When the user clicks cell C3
  And the user clicks button paste-button
  Then the raw content of C3 is "=B2*2+Sheet1!B2+Sheet1!$A$1"
  And cell-C3 reads "50"
  When the user clicks cell B2
  And the user clicks button paste-button
  Then the raw content of B2 is "=A1*2+Sheet1!A1+Sheet1!$A$1"
  And cell-B2 reads "20"
  And cell-C3 reads "90"

Scenario: Cut to another sheet
  Given the user enters "5" in A1
  And the user enters "=A1+1" in A2
  And the user clicks cell A1
  And the user shift-clicks cell A2
  And the user clicks button cut-button
  And the user clicks button add-sheet
  When the user clicks cell B1
  And the user clicks button paste-button
  Then cell-B1 reads "5"
  And the raw content of B2 is "=A1+1"
  And cell-B2 reads "1"
  And paste-button is disabled
  When the user clicks sheet tab 1
  Then cell-A1 and cell-A2 show nothing

FR-CLP-05 Clipboard after sheet changes

  • Statement: The system shall never rewrite the block of the clipboard: when a sheet is renamed or deleted, or when rows or columns are inserted or deleted, the block shall keep its raw contents as they were taken, the address of its rectangle, and the name its sheet had when it was taken. A formula pasted afterwards carries the sheet prefixes of the block: a prefix whose sheet was renamed or deleted names no sheet and gives #REF!, until a sheet takes that name. When a block in mode cut is pasted, the system shall empty its rectangle in the sheet that has, at that moment, the name recorded in the block (same name, 02, section 2.12); if no sheet has that name, then the system shall skip that step and still write the block and empty the clipboard.
  • Rationale: The clipboard is a picture taken at one moment; what it does later depends only on that picture and on the workbook as it is.
  • Verification: Test
  • Acceptance criteria:
Scenario: Renamed after the copy
  Given the user clicks button add-sheet
  And the user enters "7" in A1
  And the user clicks sheet tab 1
  And the user enters "=Sheet2!A1+1" in B1
  And the user clicks cell B1
  And the user clicks button copy-button
  And the user clicks sheet tab 2
  And the user renames the sheet to "Data"
  And the user clicks sheet tab 1
  Then the raw content of B1 is "=Data!A1+1"
  When the user clicks cell B2
  And the user clicks button paste-button
  Then the raw content of B2 is "=Sheet2!A2+1"
  And cell-B2 reads "#REF!"
  When the user clicks button add-sheet
  And the user enters "3" in A2
  And the user clicks sheet tab 1
  Then sheet-tab-3 reads "Sheet2"
  And cell-B2 reads "4"

Scenario: Cut, then the source sheet is renamed
  Given the user enters "5" in A1
  And the user clicks cell A1
  And the user clicks button cut-button
  And the user renames the sheet to "Old"
  And the user clicks button add-sheet
  When the user clicks cell B1
  And the user clicks button paste-button
  Then the active sheet is "Sheet1"
  And cell-B1 reads "5"
  And paste-button is disabled
  When the user clicks sheet tab 1
  Then cell-A1 reads "5"

Scenario: Cut, then the source sheet is deleted
  Given the user clicks button add-sheet
  And the user enters "=Sheet1!A1+1" in C3
  And the user clicks cell C3
  And the user clicks button cut-button
  And the user clicks button delete-sheet
  When the user clicks cell A2
  And the user clicks button paste-button
  Then the active sheet is "Sheet1"
  And the raw content of A2 is "=Sheet1!A1+1"
  And cell-A2 reads "1"
  And paste-button is disabled

In the second scenario the sheet added after the renaming takes the name Sheet1, which is the name recorded in the block: the paste empties A1 of that new sheet, which was empty already, and the 5 of the sheet now named Old stays.
