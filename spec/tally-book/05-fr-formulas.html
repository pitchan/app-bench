5. Functional requirements — Formulas

5.1 Language

FR-FML-01 Formula syntax

  • Statement: The system shall treat a committed string that starts with = as a formula and shall decide whether it is valid with the tokens and the grammar of 02, section 2.6. If the formula is not valid, then the system shall give the cell the value #SYNTAX! and keep the string unchanged as raw content.
  • Rationale: A formula that cannot be read is shown as such and can be corrected as it was typed.
  • Verification: Test
  • Acceptance criteria:
Scenario: Not valid
  When the user enters "=1+" in A1
  And the user enters "=(1+2" in A2
  And the user enters "=1 2" in A3
  And the user enters "=SUM(1,,2)" in A4
  And the user enters "=A1(2)" in A5
  And the user enters "=1." in A6
  And the user enters "=A$+1" in A7
  And the user enters "=" in A8
  Then cell-A1 to cell-A8 all read "#SYNTAX!"
  And the raw content of A3 is "=1 2"

Scenario: Valid, with an error value
  When the user enters "=foo" in B1
  And the user enters "=foo(1)" in B2
  And the user enters "=SUM()" in B3
  Then cell-B1 reads "#NAME?"
  And cell-B2 reads "#NAME?"
  And cell-B3 reads "#ARGS!"
  And the raw content of B1 is "=FOO"

FR-FML-02 Canonical form

  • Statement: When a valid formula is committed, the system shall store its canonical form (02, section 2.6.4) as raw content: no space outside string literals, names, references, logical literals and #REF! in capitals, number and string literals as typed, ranges normalized with each $ sign kept on its column part or row part.
  • Rationale: A formula has one writing, which the rewriting rules and the formula bar share.
  • Verification: Test
  • Acceptance criteria:
Scenario: Canonical writing
  When the user enters "= if( a1 >= 10 , ""big"" , sum( $b$2:b1 ) )" in D1
  And the user enters "=Sum( c3:a1 ) + 1.50 + .5" in D2
  And the user enters "=""a  b"" & true" in D3
  And the user enters "=b007" in D4
  Then the raw content of D1 is "=IF(A1>=10,""big"",SUM($B1:B$2))"
  And the raw content of D2 is "=SUM(A1:C3)+1.50+.5"
  And the raw content of D3 is "=""a  b""&TRUE"
  And the raw content of D4 is "=B7"

FR-FML-04 Operands of arithmetic

  • Statement: The system shall convert the operands of the arithmetic operators to numbers as 02, section 2.7.3 states: a logical value to 1 or 0, blank to 0. If an operand is a text, then the system shall give #VALUE!, even when the text is written like a number.

FR-FML-06 Comparison

  • Statement: The system shall evaluate =, <>, <, <=, > and >= as 02, section 2.7.6 states: a blank operand takes the type of the other one, texts are compared without regard to letter case, and across types any number is less than any text, which is less than any logical value.
  • Rationale: Every pair of values can be compared, with one result.

FR-FML-07 Cell references

  • Statement: The system shall evaluate a reference inside the grid to the value of its cell, blank for an empty cell, the $ signs having no effect on the value. A reference without sheet prefix names a cell of the sheet that holds the formula (FR-FML-12). If a reference is outside the grid, then the system shall give #REF!. If a range stands anywhere but as a range argument of a function that accepts ranges, then the system shall give #VALUE!. When the expression of a formula evaluates to blank, the value of the cell shall be the number 0.
  • Rationale: A formula reads other cells; a missing cell is an error and an empty one is not.
  • Verification: Test
  • Acceptance criteria:
Scenario: References

  When the user enters "=$B$1+b1" in A1

  And cell-A6 reads "#VALUE!"

FR-FML-08 Error propagation

  • Statement: When an operand of an operator is an error, the system shall give that error as the result of the operator, the error of the left operand when both are errors, and shall check this before any type rule (02, section 2.7.2). When both operands fail their conversion, the system shall give the error of the left operand.
  • Rationale: The first cause of a failure is the one shown.
  • Verification: Test
  • Acceptance criteria:
Scenario: Left first, errors before types
  When the user enters "=1/0+foo" in A1
  And the user enters "=foo+1/0" in A2
  And the user enters "=""a""+1/0" in A3
  And the user enters "=""a""&1/0" in A4
  And the user enters "=(1/0)=(1/0)" in A5
  Then cell-A1 reads "#DIV/0!"
  And cell-A2 reads "#NAME?"
  And cell-A3 reads "#DIV/0!"
  And cell-A4 reads "#DIV/0!"
  And cell-A5 reads "#DIV/0!"

FR-FML-09 Numeric errors

  • Statement: If a division has a divisor of 0, then the system shall give #DIV/0!. If a power has a base of 0 and an exponent of 0, or a negative base and an exponent that is not an integer, then the system shall give #NUM!; if it has a base of 0 and a negative exponent, then the system shall give #DIV/0!.
  • Rationale: An operation without a result says why.
  • Verification: Test
  • Acceptance criteria:
Scenario: Division and power

FR-FML-10 Circular references

  • Statement: The system shall give the value #CYCLE! to every circular cell and only to circular cells, as 02, section 2.9 defines them: a cell that can be reached from itself through the references, the ranges and the defined names of valid formulas, including those in arguments that are not evaluated. A cell that is not circular shall be evaluated normally, reading #CYCLE! as an error value from the circular cells it refers to. When a change of the workbook breaks a cycle, the cells that are no longer circular shall be evaluated normally.
  • Rationale: A loop has no result, and it is shown where it is, not everywhere downstream.
  • Verification: Test
  • Acceptance criteria:
Scenario: Loop, dependents, break
  When the user enters "=B1+1" in A1
  And the user enters "=A1+1" in B1
  And the user enters "=A1+1" in C1

  Then cell-A1, cell-B1, cell-E1 and cell-F2 read "#CYCLE!"
  And cell-C1 reads "#CYCLE!"
  And cell-D1 reads "5"
  When the user enters "10" in B1
  Then cell-A1 reads "11"
  And cell-C1 reads "12"
  And cell-D1 reads "11"

FR-FML-11 Recalculation

  • Statement: When the raw content of a cell changes, by any action of this specification, the system shall show at once the new value of every cell whose value depends on it, directly or through other cells, in any sheet. The system shall do the same when the sheets or the defined names change: a sheet added, renamed or deleted, a name defined or deleted.
  • Rationale: The workbook is always consistent with its contents.
  • Verification: Test
  • Acceptance criteria:
Scenario: Chain
  Given the user enters "=A1*2" in B1
  And the user enters "=B1+1" in C1
  And the user enters "=SUM(A1:C1)" in D1

  And cell-C1 reads "11"
  And cell-D1 reads "26"
  When the user enters "x" in A1
  Then cell-B1 reads "#VALUE!"
  And cell-C1 reads "#VALUE!"
  And cell-D1 reads "#VALUE!"

FR-FML-12 Sheet prefixes

  • Statement: The system shall accept a sheet prefix, bare or quoted, before a reference or a range, as 02, sections 2.6.1 and 2.6.2 define it, and shall evaluate that reference or range in the sheet the prefix names, letter case ignored. The system shall evaluate a reference or a range without prefix in the sheet that holds the formula, whatever the active sheet. If a prefix names no sheet, then the system shall give #REF!; the sheets are looked up at each evaluation, so the value changes as soon as a sheet takes that name. If a sheet prefix stands before anything other than a reference or a range, or if a quoted sheet name is not closed, is empty or is not immediately followed by !, then the formula is not valid.
  • Rationale: A sheet reads the cells of another sheet, and says so when that sheet does not exist.
  • Verification: Test
  • Acceptance criteria:
Scenario: Reading another sheet
  Given the user enters "5" in A1
  And the user enters "7" in A2
  And the user clicks button add-sheet
  And the user enters "100" in A1
  When the user enters "=Sheet1!A1+A1" in B1

  And the user enters "=SUM(Sheet3!A1:A2)" in B5
  And the user enters "=Sheet1!I1" in B6
  And the user enters "=Sheet1!A1:A2" in B7

  And cell-B2 reads "12"
  And cell-B3 reads "14"
  And cell-B4 reads "#REF!"
  And cell-B5 reads "#REF!"
  And cell-B6 reads "#REF!"
  And cell-B7 reads "#VALUE!"
  When the user clicks button add-sheet
  And the user enters "9" in A1
  And the user clicks sheet tab 2
  Then cell-B4 reads "9"
  And cell-B5 reads "9"

Scenario: Not valid

FR-FML-13 Canonical form of sheet prefixes

  • Statement: When a valid formula is committed, the system shall write each sheet prefix as 02, section 2.6.4 states: with the exact name of the sheet it names when such a sheet exists at that moment, and as typed otherwise; bare when the name matches ^[A-Za-z_][A-Za-z0-9_]*$, and otherwise between ' with each ' of the name doubled. The system shall not write a stored formula again when a sheet is added later.
  • Rationale: A reference to a sheet has one writing, which the rewriting rules rely on.
  • Verification: Test
  • Acceptance criteria:

FR-FML-14 Circular references across sheets

  • Statement: The system shall look for circular cells over the whole workbook, as 02, section 2.9 defines them: the precedents of a formula include the cells of the other sheets that its references and ranges point to, and the cells of the targets of the defined names it uses. The system shall give #CYCLE! to every circular cell of every sheet and only to them, and shall evaluate the cells again when a change in any sheet creates or breaks a cycle.
  • Rationale: A loop that goes through another sheet is still a loop.

5.2 Functions

FR-FUN-01 Function calls and arguments

  • Statement: The system shall recognize the 47 function names of 02, section 2.6.3 in any letter case. If the name of a call is not one of them, then the system shall give #NAME?. If the number of arguments is not allowed for the function, then the system shall give #ARGS!. These two checks shall be made in this order and before any argument is evaluated. The system shall then process the arguments in order and give the first error met, unless the function states otherwise (02, section 2.8.2). A parameter that 02, section 2.8.3 writes between [ and ] may be left out; any other number of arguments gives #ARGS!.
  • Rationale: A wrong call is reported before its arguments are.

  • Acceptance criteria:
