7. Functional requirements — History

The history is a list of steps. There is one history for the whole workbook. It is empty when the page loads: on a new workbook and after every reload (FR-PER-03).

FR-HIS-01 History steps

  • Statement: The system shall record exactly one step for each of the actions below, and no step for anything else (moving or extending the selection, copying, cutting, cancelling an edit, an action that this specification says changes nothing).

    Action A step is recorded
    Commit of an edit (FR-EDT-03) when the raw content of the cell changes
    Clear (FR-EDT-06) when one cell at least of the selection is not empty
    Format (FR-NUM-03) when the format of one cell at least of the selection changes
    Insert row, insert column, delete row, delete column (FR-STR-01, FR-STR-02) always
    Paste (FR-CLP-01, FR-CLP-03) always
    The workbook actions of FR-HIS-05 as FR-HIS-05 states

    A step holds the state of the workbook before the action and after it. That state is: the sheets, in their order, each with its name, the raw content and the format of every cell, its anchor and its active cell; the defined names with their targets; and which sheet is active. "After" is taken when the user action that caused the step is complete: for a commit by Enter or Tab, after the active cell has moved; for a commit caused by a click on a cell, after that click has set the selection. When a step is recorded, the steps that could be redone shall be discarded.

  • Rationale: Every change of the workbook can be taken back, one user action at a time.

  • Verification: Test

  • Acceptance criteria:

Scenario: What counts
  When the page loads
  Then undo-button is disabled and redo-button is disabled
  When the user clicks cell B2
  And the user shift-clicks cell C3
  And the user clicks button copy-button
  And the user presses Delete on the grid
  Then undo-button is disabled
  When the user enters "1" in A1
  Then undo-button is enabled
  When the user enters "1" in A1
  And the user clicks button undo-button
  Then cell-A1 shows nothing
  And undo-button is disabled

FR-HIS-02 Undo

  • Statement: When the user clicks undo-button, or presses Control+Z on the grid, while a step can be undone, the system shall restore the state of the workbook that the most recent step that is not undone holds as "before", and shall show every cell, name-box, formula-input, format-select, the sheet tabs, sheet-name-input and name-list accordingly. That step can then be redone. The clipboard shall not change. While no step can be undone, the system shall disable undo-button.
  • Rationale: The user goes back to exactly what was on the screen.
  • Verification: Test
  • Acceptance criteria:
Scenario: Undo a row deletion and a commit
  Given the user enters "5" in A1
  And the user enters "=A1+A2" in B1
  And the user clicks cell A1
  And the user shift-clicks cell H1
  When the user clicks button delete-row
  Then cell-B1 shows nothing
  When the user clicks button undo-button
  Then cell-A1 reads "5"
  And the raw content of B1 is "=A1+A2"
  When the user clicks cell A1
  And the user shift-clicks cell H1
  And the user clicks button undo-button
  Then cell-B1 shows nothing
  And cell-A1 reads "5"
  And the selection is "B1"

In this scenario the first undo restores the selection A1:H1. The second undo takes back the commit of B1: the selection before that commit was B1.

FR-HIS-03 Redo

  • Statement: When the user clicks redo-button, or presses Control+Y on the grid, while a step can be redone, the system shall restore the state of the workbook that the most recently undone step holds as "after", and shall show it in the same way. That step can then be undone again. While no step can be redone, the system shall disable redo-button.
  • Rationale: An undo made by mistake is taken back.
  • Verification: Test
  • Acceptance criteria:
Scenario: Undo twice, redo, new action
  Given the user enters "1" in A1
  And the user enters "2" in A2
  When the user presses Control+Z on the grid
  And the user presses Control+Z on the grid
  Then cell-A1 and cell-A2 show nothing
  When the user presses Control+Y on the grid
  Then cell-A1 reads "1"
  And cell-A2 shows nothing
  And the selection is "A2"
  And redo-button is enabled
  When the user enters "7" in C3
  Then redo-button is disabled
  And cell-A2 shows nothing

FR-HIS-04 History limit

  • Statement: The system shall keep at most 20 steps that can be undone, for the whole workbook. When a step is recorded while 20 are kept, the system shall discard the oldest one.
  • Rationale: The memory used by the history is bounded.
  • Verification: Test
  • Acceptance criteria:
Scenario: Twenty-one commits
  Given the user enters "1" in A1, "2" in A2, and so on up to "12" in A12
  And the user enters "13" in B1, "14" in B2, and so on up to "21" in B9
  When the user clicks button undo-button 20 times
  Then undo-button is disabled
  And cell-A1 reads "1"
  And cell-A2 shows nothing

FR-HIS-05 Workbook actions

  • Statement: The system shall record exactly one step for each of the actions below, under the condition given, in the same history as the actions of FR-HIS-01.

    Action A step is recorded
    Add a sheet (FR-SHT-02) always
    Rename a sheet (FR-SHT-04) when the name is accepted and differs from the current name
    Delete a sheet (FR-SHT-06) always
    Define a name (FR-NAM-01), delete a name (FR-NAM-04) when the action is accepted
    Sort (FR-SRT-01) when one row at least changes place
    Fill down, fill right (FR-FIL-01, FR-FIL-02) when the selection has two rows or more, two columns or more
    Fill series (FR-FIL-03) when one line at least is continued
    Replace all (FR-FND-03) when the raw content or the format of one cell at least changes
    Import (FR-CSV-05) when the text is read without error

    The system shall record no step for: switching sheets, find-next, csv-export, typing in a field or checking a box, an action that is refused with a message, and an action on a disabled control. A step of these actions holds the same state as any step (FR-HIS-01): undoing it restores the sheets, their names, the defined names and their targets, the active sheet and every selection.

  • Rationale: Every change of the workbook, whatever its size, is taken back with one undo.

  • Verification: Test

  • Acceptance criteria:

Scenario: One step per action
  Given the user enters "2" in A1
  And the user enters "1" in A2
  And the user clicks cell A1
  And the user shift-clicks cell A2
  When the user clicks button sort-asc
  And the user defines the name "Pair"
  And the user clicks button add-sheet
  And the user renames the sheet to "Notes"
  And the user fills csv-text with "a,b"
  And the user clicks button csv-import
  And the user clicks button csv-export
  And the user fills find-input with "a"
  And the user clicks button find-next
  And the user fills find-input with "zzz"
  And the user clicks button replace-all
  And the user renames the sheet to "Notes/2"
  And the user defines the name "A1"
  And the user clicks button sort-asc
  And the user clicks button fill-down
  Then cell-A1 reads "a"
  When the user clicks button undo-button
  Then cell-A1 shows nothing
  And the active sheet is "Notes"
  When the user clicks button undo-button
  Then sheet-tab-2 reads "Sheet2"
  When the user clicks button undo-button
  Then there is 1 sheet tab
  And name-item-1 reads "Pair = Sheet1!A1:A2"
  When the user clicks button undo-button
  Then there are no name items
  And cell-A1 reads "1"
  When the user clicks button undo-button
  Then cell-A1 reads "2"
  When the user clicks button undo-button 2 times
  Then undo-button is disabled
  And cell-A1 shows nothing
  When the user clicks button redo-button 7 times
  Then redo-button is disabled
  And the active sheet is "Notes"
  And cell-A1 reads "a"
  And cell-B1 reads "b"
  And name-item-1 reads "Pair = Sheet1!A1:A2"

In this scenario seven steps are recorded: two commits, the sort, the name, the sheet, its renaming and the import. The other actions of the "When" part record none: an export, a search, a replacement that matches no cell, a renaming and a name that are refused, a sort that moves no row and a fill on a selection of one row.

FR-HIS-06 Undo across sheets

  • Statement: The system shall keep one history for the whole workbook, whatever the sheet each action took place in, with the limit of FR-HIS-04 for all sheets together. When a step is undone or redone, the system shall restore the whole state it holds, the active sheet included: an undo shows again the sheet in which the action took place, with the selection it had before the action, and gives back to every other sheet the selection it had at that moment, whatever sheet is active and whatever was selected since.
  • Rationale: The user sees what an undo changes, because the undo shows the place where it changes it.
  • Verification: Test
  • Acceptance criteria:
Scenario: Undo goes back to the sheet of the action
  Given the user enters "1" in A1
  And the user clicks button add-sheet
  And the user enters "x" in B2
  And the user clicks sheet tab 1
  And the user clicks cell D4
  When the user clicks button undo-button
  Then the active sheet is "Sheet2"
  And cell-B2 shows nothing
  And the selection is "B2"
  When the user clicks sheet tab 1
  Then the selection is "A2"
  And cell-A1 reads "1"
  When the user clicks button undo-button
  Then there is 1 sheet tab
  And the active sheet is "Sheet1"
  And the selection is "A2"
  When the user clicks button redo-button
  Then the active sheet is "Sheet2"
  And the selection is "A1"
  When the user clicks button redo-button
  Then cell-B2 reads "x"
  And the selection is "B3"
  And redo-button is disabled

In this scenario the first undo takes back the commit of x: before that commit the active sheet was Sheet2 with B2 selected, and Sheet1 had the selection A2 left by the commit of 1; the click on D4 is not a step and is not kept. The second undo takes back the adding of Sheet2; the workbook still shows Sheet1, where the user was when the sheet was added.
