11. Functional requirements — Sort, fill, find and CSV

Every action of this file acts on the active sheet. Each one that changes the workbook is one step of the history (FR-HIS-05).

11.1 Sort

FR-SRT-01 Sorting rows

  • Statement: When the user clicks sort-asc or sort-desc, the system shall reorder the rows of the selection. A row of the selection is the cells of one row of the sheet that are inside the selection; the key column is the column of the active cell. The system shall place the rows of the selection in the ascending order of their keys for sort-asc, in the descending order for sort-desc (02, section 2.14), each cell moving with its raw content and its format. The cells outside the selection shall not move. The selection shall not change: the anchor and the active cell keep their addresses. If no row of the selection changes place, then the system shall change nothing and create no history step.
  • Rationale: A table is put in order on one of its columns, without touching what is beside it.

FR-SRT-02 Sorting order

  • Statement: The system shall order the keys as 02, section 2.14 states. Ascending: number cells by value, then text cells without regard to letter case, then FALSE, then TRUE, then error cells, then empty cells. Descending: error cells, then TRUE, then FALSE, then text cells in decreasing order, then number cells by decreasing value, then empty cells. Empty cells come last in both orders. A cell is ordered by the value it has before the sort, a formula cell by its result; a cell that holds the empty text is a text cell.
  • Rationale: Any column can be sorted, whatever it holds, with one known result.

FR-SRT-04 Sorted formulas

  • Statement: When rows are sorted, the system shall move the raw content of each cell as it is: a formula that moves is not adjusted (02, section 2.10.3 does not apply), so its references name the same addresses as before. The system shall rewrite no formula of any other cell and change no target of a defined name. The keys are the values before the sort; after the sort every cell is evaluated again, so the values of the moved formulas can differ from their keys.
  • Rationale: One simple rule: a sort moves contents and changes none.

  • Acceptance criteria:

11.2 Fill

FR-FIL-01 Fill down

  • Statement: When the user clicks fill-down while the selection has two rows or more, the system shall, for each column of the selection, write into each cell of the selection below its first row: the raw content of the cell of that column in the first row of the selection, adjusted as 02, section 2.10.3 states by the offset between the two cells when it is a valid formula and unchanged otherwise; and the format of that cell. An empty cell in the first row makes the cells below it empty. The selection shall not change. If the selection has one row, then the system shall change nothing and create no history step.
  • Rationale: A formula typed once is repeated down a column, each copy reading its own row.
  • Verification: Test
  • Acceptance criteria:
Scenario: Values, formulas and formats
  Given the user enters "5" in A1
  And the user enters "=A1*2+$A$1" in B1
  And the user enters "x" in C1
  And the user enters "=D12+SUM(A11:A12)" in D1
  And the user enters "old" in A2
  And the user enters "z" in E2
  And the user clicks cell A1
  And the user sets the format to "fixed2"
  When the user clicks cell A1
  And the user shift-clicks cell E3
  And the user clicks button fill-down
  Then cell-A2 reads "5.00"
  And cell-A3 reads "5.00"
  And the raw content of B2 is "=A2*2+$A$1"
  And the raw content of B3 is "=A3*2+$A$1"
  And cell-B3 reads "15"
  And cell-C3 reads "x"
  And the raw content of D2 is "=#REF!+SUM(#REF!)"
  And cell-E2 shows nothing
  When the user clicks button undo-button
  Then cell-A2 reads "old"
  And cell-E2 reads "z"
  And the selection is "A1:E3"
  When the user clicks cell A1
  And the user shift-clicks cell E1
  And the user clicks button fill-down
  Then redo-button is enabled

In this scenario the last click acts on a selection of one row: nothing changes, no step is created, and the step that was undone can still be redone.

FR-FIL-03 Fill series

  • Statement: When the user clicks fill-series, the system shall take the lines of the selection: when the selection has one row, one line, that row from left to right; otherwise one line per column of the selection, from top to bottom. The system shall continue each line that can be continued (02, section 2.15): its first two cells hold numbers that are not formulas, it has three cells or more, and every value is in range. The cells from the third on receive the raw content P(v) of their value and the format of the first cell of the line; the step is the difference between the first two values, and each value is computed from the first one. The lines that cannot be continued shall not change. The selection shall not change. If no line is continued, then the system shall change nothing and create no history step.
  • Rationale: A list of numbers or of dates is extended from its first two terms.

11.3 Find and replace

The rules on matching and replacing are in 02, section 2.16. The needle is the value of find-input, the replacement string the value of replace-input, both taken as typed; match case is on when find-case is checked, whole cell when find-whole is checked.

FR-FND-01 Find next

  • Statement: When the user clicks find-next, the system shall count the cells of the active sheet that match (02, section 2.16) and show TXT-09 in find-status, {n} being that count. If one cell at least matches, then the system shall make anchor and active cell the first matching cell that comes after the active cell in visiting order, the search going on from A1 after H12 and ending with the active cell itself. If no cell matches, the selection shall not change. The search reads raw contents: a formula is searched in its text, not in its result. The system shall change no cell and create no history step. Pressing Enter in find-input shall start no action, and shall neither reload the page nor navigate.
  • Rationale: The user walks through the cells that hold a text, formulas included.
  • Verification: Test
  • Acceptance criteria:
Scenario: Walking through the matches

  When the user clicks button find-next
  Then the selection is "A1"
  When the user fills find-input with "5"
  And the user clicks button find-next
  Then find-status reads "Matches: 1"
  And the selection is "C3"
  When the user clicks button find-next
  Then the selection is "C3"
  When the user fills find-input with "zzz"
  And the user clicks button find-next
  Then find-status reads "Matches: 0"
  And the selection is "C3"

  And the user clicks button find-next
  Then find-status reads "Matches: 0"
  And undo-button is enabled
  When the user clicks button undo-button 5 times

In this scenario A2 shows 5 and is not found by the needle 5: its raw content is =LEN("apple"). The five undos are those of the five commits: no search created a step.

FR-FND-02 Search options

  • Statement: The system shall apply the two options of 02, section 2.16 to find-next and to replace-all. Without match case, a letter A–Z matches its capital and its small form, and every other character matches itself only; with match case, every character matches itself only. With whole cell, a cell matches when its whole raw content matches the needle; without it, when a part of its raw content does. With an empty needle no cell matches.

FR-FND-03 Replace all

  • Statement: When the user clicks replace-all, the system shall, for each matching cell of the active sheet (02, section 2.16), build the new string of that section and commit it to the cell under 02, section 2.2. The system shall then show TXT-10 in find-status, {n} being the number of cells that matched. The whole action is one history step, created when the raw content or the format of one cell at least has changed, and not otherwise. The selection, the other sheets and the targets of the defined names shall not change. Pressing Enter in replace-input shall start no action, and shall neither reload the page nor navigate.
  • Rationale: A text is corrected everywhere in a sheet in one action, and taken back in one.

The replacement string is inserted as typed, whatever the letter case of the text it replaces.

11.4 CSV

The rules on writing and reading a CSV text are in 02, section 2.17. The CSV controls are in csv-panel (03, section 3.2). The text is exchanged through csv-text only: no file is read or written.

FR-CSV-01 Export of shown values

  • Statement: When the user clicks csv-export while csv-raw is not checked, the system shall set the value of csv-text to the CSV text of the active sheet, written as 02, section 2.17.1 states. With R the last row that holds a cell that is not empty and C the last column that holds a cell that is not empty, the text has one record per row from 1 to R, each with one field per column from A to C: the text shown by the cell, with its format, and the empty field for a cell that shows nothing. The rows after R and the columns after C are left out; a format alone does not make a cell count. When every cell of the sheet is empty, the text is the empty string. The export shall change nothing in the workbook and create no history step.
  • Rationale: What the user sees goes out as it is seen.
  • Verification: Test
  • Acceptance criteria:
Scenario: A small table
  Given the user enters "Item" in A1
  And the user enters "Price" in B1

  And the user enters "total" in A5
  And the user enters "=SUM(B2:B3)" in B5

FR-CSV-03 CSV quoting

  • Statement: When a CSV text is written, the system shall put between " every field that contains ", ,, CR or LF, doubling each " of the field, and shall write every other field as it is, the empty field and the fields with leading or trailing spaces included. The records shall be separated by one LF, with nothing after the last record.
  • Rationale: The text can be read back without ambiguity by any CSV reader.
  • Verification: Test
  • Acceptance criteria:
Scenario: Quotes, commas and spaces
  Given the user enters "say ""hi""" in A1
  And the user enters "a,b" in B1
  And the user enters " padded " in C1
  And the user enters """" in A2
  And the user enters "plain" in B2
  And the user enters "'=x" in A3
  And the user enters "=""a""&"",""" in B3
  When the user clicks button csv-export
  Then csv-text has the value
    """
    "say ""hi""","a,b", padded 
    """",plain,
    =x,"a,",
    """
  When the user checks csv-raw
  And the user clicks button csv-export
  Then csv-text has the value
    """
    "say ""hi""","a,b", padded 
    """",plain,
    '=x,"=""a""&"",""",
    """

In this scenario the first record ends with the field padded, whose last character is a space.

FR-CSV-04 CSV reading

  • Statement: When the user clicks csv-import, the system shall read the value of csv-text as 02, section 2.17.2 states: quoted fields with "" for one ", commas inside quoted fields, each line break inside a quoted field replaced by one space, bare fields kept with their spaces, an empty line as a record of one empty field, and no record started by a final line break. If the value is the empty string, then the system shall change nothing in the workbook and show TXT-11 in csv-message. If the text is malformed, then the system shall change nothing in the workbook and show TXT-12 in csv-message. In both cases no history step is created. The value of csv-text shall not be changed by the import.
  • Rationale: A text that cannot be read as CSV is refused as a whole; nothing is half imported.
  • Verification: Test
  • Acceptance criteria:
Scenario: Fields of every kind

    "x
    y",2

    last"q
    
    """

  And cell-A2 reads "x y"
  And cell-B2 reads "2" and has data-kind "number"
  And cell-A3 has data-kind "empty"
  And cell-A4 reads "last""q"
  And cell-A5 has data-kind "empty"
  And csv-message reads "Imported: 5 | Dropped: 0"

Scenario: Refused texts
  Given the user enters "keep" in A1
  When the user clicks button csv-import
  Then csv-message reads "Nothing to import"

  And the user clicks button csv-import
  Then csv-message reads "Invalid CSV"

FR-CSV-05 Import into the sheet

  • Statement: When a CSV text is read without error, the system shall, in this order: (1) make every cell of the active sheet empty, the formats being kept; (2) commit each field that is not empty, of record number i and field number j, to the cell of row i and column number j of the active sheet, under 02, section 2.2, when i is at most 12 and j at most 8, and drop it otherwise; (3) show TXT-13 in csv-message, {k} being the number of fields committed and {d} the number of fields that are not empty and were dropped. The whole import is one history step, always created. The selection, the other sheets, the formulas of the other sheets and the targets of the defined names shall not change. Pressing Enter in csv-text shall start no action, and shall neither reload the page nor navigate.
  • Rationale: A sheet is replaced by a table typed or pasted as text; what does not fit is counted, not hidden.
  • Verification: Test
  • Acceptance criteria:
