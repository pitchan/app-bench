9. Non-functional requirements

NFR-PKG-01 Single file delivery

  • Statement: The system shall be delivered as one file named index.html, starting with <!DOCTYPE html>, containing all of its HTML, CSS, JavaScript and SVG inline.
  • Rationale: The page opens directly from the file system with no installation.
  • Verification: Test
  • Acceptance criteria:
Scenario: Opened from disk
  When index.html is opened through a file:// URL
  Then the grid is usable

NFR-NET-01 No network access

  • Statement: The system shall not issue any network request (scripts, stylesheets, fonts, images, data) other than loading index.html itself. Saving the workbook (FR-PER-01) and exchanging CSV text (file 11) shall use no request.
  • Rationale: The page works offline and loads instantly.
  • Verification: Test
  • Acceptance criteria:
Scenario: No request
  When the page loads and the user enters values and formulas, adds a sheet, exports and imports a CSV text and reloads the page
  Then no request other than the page itself was made

NFR-DLG-01 No native dialogs

  • Statement: The system shall not call window.alert, window.confirm or window.prompt, and shall not open any other modal dialog. Every action is started by a control of 03-ui-contract and is carried out at once, without asking for a confirmation: deleting a sheet, deleting a name and importing a CSV text included. Every message is shown in its message element (03, section 3.5).
  • Rationale: Every message has its place in the page, and what was done by mistake is taken back with undo.
  • Verification: Test
  • Acceptance criteria:
Scenario: No dialog in any flow
  When the user performs every flow of this specification
  Then no native dialog is opened

NFR-ERR-01 No script errors

  • Statement: The system shall not throw any uncaught exception nor leave any rejected promise unhandled, from page load and during every flow of this specification, whatever string is committed to a cell, typed in a field, given as CSV text or found in localStorage (FR-PER-04). Every test of this specification fails when the page throws such an error during that test.
  • Rationale: A script error stops the page halfway; what still works afterwards is not a working page.
  • Verification: Test
  • Acceptance criteria:
Scenario: Clean run
  When the page loads and the user performs every flow of this specification
  Then the page threw no uncaught error

Scenario: Hostile contents

  And the user enters "<b>bold</b>" in A4

  And the user enters "=VLOOKUP(,,)" in A6
  And the user renames the sheet to "<i>x</i>"
  And the user defines the name "<b>"
  And the user fills csv-text with """"

  And name-message reads "Invalid name"
  And csv-message reads "Invalid CSV"

NFR-A11Y-01 Native controls and accessible names

  • Statement: The system shall use native <button>, <select>, <input> and <textarea> elements for every control of 03-ui-contract, with the accessible names given there, so that each control can be found by its role and exact accessible name. Disabled controls shall use the disabled attribute. For each checkbox (find-case, find-whole, csv-raw), its panel shall contain a visible element whose text is exactly the label of the checkbox (03, section 3.2).
  • Rationale: Controls work with assistive technologies and the keyboard.
  • Verification: Test
  • Acceptance criteria:
Scenario: Roles and names

  And there is exactly one button named "Undo", and it is disabled
  And there is exactly one combobox named "Number format"

  And there is exactly one button named "Delete sheet", and it is disabled
  And there is exactly one button named "Delete name"
  And there is exactly one textbox named "Sheet name"
  And there is exactly one textbox named "Name"
  And there is exactly one textbox named "Find"
  And there is exactly one textbox named "Replace with"
  And there is exactly one textbox named "CSV"
  And there is exactly one checkbox named "Match case", and it is not checked
  And there is exactly one checkbox named "Whole cell"
  And there is exactly one checkbox named "Raw contents"
  And find-panel contains a visible element whose text is exactly "Match case"
  And find-panel contains a visible element whose text is exactly "Whole cell"
  And csv-panel contains a visible element whose text is exactly "Raw contents"

NFR-A11Y-02 Grid semantics

  • Statement: The system shall expose the active sheet as a grid: one element with role="grid" and the accessible name Sheet, that can receive the focus; 13 elements with role="row" inside it (the row of column headers and the 12 rows); 8 elements with role="columnheader", 12 with role="rowheader" and 96 with role="gridcell", each inside its row; aria-selected="true" on the active cell only. These counts are the same whether the elements are counted by their explicit role attribute or by their computed accessibility role (Playwright getByRole) inside grid; a corner element (03, section 3.2) is counted in none of them.
  • Rationale: Assistive technologies can read the rows, the columns and which cell is selected.
  • Verification: Test
  • Acceptance criteria:
Scenario: Roles
  When the page loads
  Then there is exactly one grid named "Sheet"
  And the grid contains 13 rows, 8 column headers, 12 row headers and 96 grid cells
  And exactly one grid cell has aria-selected "true", and it is cell-A1

NFR-A11Y-03 Sheet tabs and name list semantics

  • Statement: The system shall expose the sheets as tabs: one element with role="tablist" and the accessible name Sheets, containing one element with role="tab" per sheet, in the order of the sheets, each a native <button> whose accessible name is exactly the name of its sheet, with aria-selected="true" on the tab of the active sheet only. No other element of the page shall have the role tab. The system shall expose the defined names as a list: one element with role="list" and the accessible name Names, containing one element with role="listitem" per defined name and no other list item. These counts are the same whether the elements are counted by their explicit role attribute or by their computed accessibility role (Playwright getByRole).
  • Rationale: Assistive technologies can tell how many sheets and names there are, and which sheet is shown.
  • Verification: Test
  • Acceptance criteria:
Scenario: Tabs and list
  Given the user clicks button add-sheet
  And the user renames the sheet to "Q1 data"
  And the user defines the name "Top"
  Then there is exactly one tablist named "Sheets"
  And the tablist contains 2 tabs
  And there is exactly one tab named "Q1 data", and it has aria-selected "true"
  And there is exactly one tab named "Sheet1", and it has aria-selected "false"
  And there is exactly one list named "Names"
  And the list contains 1 list item
