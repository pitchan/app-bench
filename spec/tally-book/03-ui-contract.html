The elements are listed in reading order. Placement, sizes and styles are free (08-rendering sets the limits). main and formula bar only name groups of this outline: no element and no data-testid is required for them. The reading order is not checked. No element carries a positive tabindex, no control carries a negative tabindex, and the page does not handle the Tab key outside formula-input: every control that is not disabled, each sheet tab included, is reached with the Tab key.

The four panels are part of the page at all times: they are not placed in a dialog, in a closed <details> element, in a menu or behind a control that has to be opened first.

3.2 Element identifiers

Each element below shall carry the attribute data-testid with exactly the given value, unique in the page.

Presence:

  • Permanent: present and visible at all times.
  • Conditional: visible only in the situation the requirements describe; otherwise absent or not visible.
  • Per item: one element per item of a list that changes; the requirement states how many there are.

"Visible" and "not visible" have the meanings of README, section 2.5.

Grid

The grid shows the cells of the active sheet. Its elements are the same whatever the active sheet: switching sheets changes what they show, not their data-testid.

data-testid Element Content / attributes Presence
grid any element with role="grid", aria-label="Sheet" and tabindex="0" contains the headers and the cells Permanent
col-header-<column> any element with role="columnheader", one per column, col-header-A to col-header-H Text: the column letter Permanent
row-header-<row> any element with role="rowheader", one per row, row-header-1 to row-header-12 Text: the row number Permanent
cell-<address> any element with role="gridcell", one per cell, cell-A1 to cell-H12 Text: FR-GRD-02. Attributes below. Permanent

The headers and the cells of one row of the sheet are inside one element with role="row"; the column headers are inside one element with role="row" too. Each of these roles is set with an explicit role attribute on the element, native table elements included (<tr role="row">, <th role="columnheader">, <td role="gridcell">). A <table> built this way is one way to do it. The row of column headers may contain one extra corner element before col-header-A: it carries role="presentation" and no data-testid, and it is none of the column headers, row headers or cells. No other element inside grid carries an explicit or implicit role row, columnheader, rowheader or gridcell.

A cell stays present and takes part in the layout whatever its content: an empty cell has an empty text and keeps a non-zero width and height.

Attributes of every cell-<address> element, kept up to date at all times, for the cell of that address in the active sheet:

Attribute Value
data-kind The type of the value of the cell: empty, number, text, logical or error. empty only for an empty cell. A cell that holds a date has the kind number.
aria-selected "true" on the active cell, "false" on every other cell.
data-in-selection "true" on every cell of the selection (the active cell included), "false" on every other cell.

The text content of a cell element is the text shown (02, section 2.5), with nothing added: no marker, no hidden text, no formula.

Controls

A control is every <button>, <select>, <input> and <textarea> of this section, the sheet tabs included. The workbook controls are all the controls except formula-input.

A control that a requirement declares disabled carries the disabled attribute; otherwise it does not. The rules below disable controls, and no other rule does:

Controls Disabled while
every workbook control the system is in the editing state (FR-EDT-02)
undo-button no step can be undone (FR-HIS-02)
redo-button no step can be redone (FR-HIS-03)
paste-button the clipboard is empty (FR-CLP-01)
add-sheet the workbook has five sheets (FR-SHT-02)
delete-sheet the workbook has one sheet (FR-SHT-06)

formula-input is never disabled.

A label is given with a <label> element bound to its control (or with aria-label), so that the accessible name of the control is exactly the label. For each checkbox (find-case, find-whole, csv-raw), its panel (find-panel for the first two, csv-panel for the third) contains an element that is visible (README, section 2.5) and whose text (README, section 2.5) is exactly the label of the checkbox: the <label> element bound to it, or another element when the name is given with aria-label. This element shall not use display: contents.

3.3 Keys

Keys handled while the grid element has the focus:

Key Effect
ArrowUp, ArrowDown, ArrowLeft, ArrowRight FR-SEL-02
the same with Shift held FR-SEL-03
Delete, Backspace FR-EDT-06
Enter FR-EDT-01
Control+Z FR-HIS-02
Control+Y FR-HIS-03

While in the editing state, these keys have no effect other than preventDefault(), except Enter, which still gives the focus to formula-input (FR-EDT-02).

Keys handled while formula-input has the focus:

Key Effect
Enter, Tab FR-EDT-03
Escape FR-EDT-04

Tab with Shift held is not handled in formula-input: the browser keeps its default action and moves the focus backwards.

For each key listed above, the system shall call preventDefault() on its keydown event: once the event has been dispatched, its defaultPrevented is true (the page does not scroll on an arrow key, and Tab without Shift in formula-input does not move the focus). This is verified under the requirement listed for that key. No other key is required. Letter keys are compared without regard to their case.

No key is handled in the other fields (sheet-name-input, name-input, find-input, replace-input, csv-text): typing in them does nothing but change their value, and the actions are started by the buttons only. Pressing Enter in one of them shall neither reload the page nor navigate (no form is submitted). This is verified under the requirement of the button of that field: FR-SHT-04 for sheet-name-input, FR-NAM-01 for name-input, FR-FND-01 for find-input, FR-FND-03 for replace-input, FR-CSV-05 for csv-text.

3.4 Fields

The values of the fields other than formula-input are set by the user, and by the system in these cases only:

Field Set by the system
sheet-name-input To the name of the active sheet: when the page loads, and after each of these actions: switching sheets (FR-SHT-03), adding a sheet, deleting a sheet, a renaming that is accepted, undo, redo. A renaming that is refused leaves the value as typed.
name-input To the empty string: when the page loads, and after a name is defined or deleted (not when the action is refused).
find-input, replace-input To the empty string when the page loads.
find-case, find-whole, csv-raw Unchecked when the page loads.
csv-text To the empty string when the page loads; to the exported text by csv-export (FR-CSV-01).

"When the page loads" includes every reload: these fields are not saved (FR-PER-03), and the page shall not let the browser put back what they held before the reload.

Typing in one of these fields does not start the editing state and creates no history step.

3.5 Messages

sheet-message, name-message, find-status and csv-message each belong to a group of buttons:

Message Buttons of its group
sheet-message add-sheet, rename-sheet, delete-sheet
name-message define-name, delete-name
find-status find-next, replace-all
csv-message csv-export, csv-import

A click on a button of the group that is not disabled first removes the text of the message, then sets the text that the requirement of that button states, if it states one. The message is visible when it has a text and not visible otherwise. Nothing else changes a message: not an action of another group, not undo or redo, not switching sheets. When the page loads, no message is visible.
